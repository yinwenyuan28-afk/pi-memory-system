# 网站文档内容梳理

整理日期：2026-10-11。读者是考虑安装或已经安装扩展的 Pi 用户。依据是仓库 Markdown 清单、现有网站文档、关键原文与当前源码的静态核对。未调用真实模型，也未操作真实记忆库。本文供内容维护使用，已从 VitePress 构建和搜索中排除。

## 结论与阅读路径

仓库中有不少值得公开说明的内容，但原文通常面向开发和维护，包含旧状态、个人路径、原始记忆样本、事故与提示词指令。网站采用面向用户的重新表述，说明“什么时候发生、保存什么、如何使用、如何判断没有生效”。

推荐阅读路径：快速开始 → 配置召回 → 记忆如何工作 → 查看与修正。遇到具体问题时，转到项目与 profile、后台恢复、配置、命令和数据说明。

网站现有中英文各 12 页文档：最初各 6 页，资料梳理后新增 5 个主题，随后补充“上下文与渐进式设计”。侧栏分为开始使用、理解记忆系统、日常使用、配置与参考四组。

## 原文存在的差异

这些差异用于解释为什么不能直接复制原文，本轮只更新网站用户说明，没有改写根目录的架构或定义资料。

| 原文或旧说法 | 当前核验结果 | 网站表述 |
| --- | --- | --- |
| 架构说明开头：尚未用项目标签过滤；项目定义 §7：没有读侧消费者 | `hybrid-recall.ts`、`util/recall-score.ts` 已消费标签做加权；没有硬过滤 | 自动召回可按项目排序；跨项目仍可命中 |
| 项目定义中的 `global`“无条件注入” | 通用记录不降权，但仍受查询相关性、条数、预算与时序约束 | 不因项目归属降权，不保证每次注入 |
| 架构 §7 部分段落仅描述会话判定及旧 fallback | `l1_commit` 已优先核验逐条 `projectEvidence`；无可用项目的 self 降 unknown | 明确逐条证据优先、旧调用会话判定兜底、禁止靠 cwd 猜项目 |
| 架构 §8.2 写软阈值 600 秒 | `timeout-config.ts` 的默认值是 `600000 + 30000`；配置可覆盖 | 内置软阈值 10 分 30 秒，硬上限 30 分钟 |
| “开启向量化、500 条阈值”容易被理解成所有向量操作的必要条件 | `backfill.ts` 手动回填只检查服务；`hybrid-recall.ts` 查询已有向量未检查自动写入开关 | 自动写入开关、阈值、历史回填与查询分开说明 |
| 旧注入点分析还把 L3 目标写成 USER.md，并描述旧刷新链 | `user-file.ts`、L3 工具写提议稿；人工并入才写正式画像 | 提议需审阅并入，新会话使用正式快照 |
| “并入提议稿”可能被读成自动覆盖旧画像 | 2026-10-10 的 add 策略保留 live，并按精确文本去重追加 | 默认追加；改写文本不会自动替换旧条目；完整替换须显式选择 |
| l1-admin 原文同时保留逐行过滤、LWW、旧命令未注册等不同时间口径 | 当前加载器按同 ID 最后状态，`index.ts` 已注册 health/quality/stats；旧说明不全同步 | 不照搬旧维护语义，命令表按当前注册核验 |
| 旧提示词分析有 skill-feed“5-role”说法 | 当前是 user、assistant、tool_call、tool_result，丢弃 system/thinking | 说明包含工具记录且与 L0 独立，不宣传旧角色数 |
| 旧 agents 文本称偏好由 memory-reviewer 处理 | 旧 reviewer 已停用；skill 仍应与个人偏好分开 | 只说明类型边界，不把旧 reviewer 写成现行用户入口 |

## 源码设计亮点的补充

新增中英文[上下文与渐进式设计](./docs/context-design.md)，并从记忆原理、召回与数据页互链。正文按使用效果解释设计，源码依据放在引用块中。

- **注入位置**：`index.ts` 的 `context` 在最后一条 user 后插入，工具调用后的模型请求仍保持该锚点；无 user 才追加。
- **持久化边界**：核查本机 Pi 的 `dist/core/extensions/runner.js`，`emitContext()` 先 `structuredClone(messages)`；`dist/core/sdk.js` 将它接到 `transformContext`，agent-core 在构造模型请求时使用变换结果。自动块不会写回主会话状态。主动工具结果与生成回答则可能持久化，L0/L1 自身的 JSONL 也继续保存。
- **按需加载**：完整保存契约通过 `load_memory_rules` 加载，默认 once；一次 `l1_commit` 调用结束后清除，`agent_end` 也清理。always 是显式选择。完整归档指南通过 `l2_archive_guide` 按需读取，只影响后台整理上下文。
- **控制数量和长度**：自动最多 3 条，主动默认 5 条，默认单条正文 300 字符、总正文预算 2,000 字符。这些不包含工具描述、包装或固定背景，不能宣传成扩展总 token 上限。
- **后台上下文分开**：`spawn.ts` 的 `buildSpawnArgs()` 设置独立 system prompt、工具范围、no-skills/no-context-files，子进程标记跳过前台注入。通知使用自定义 entry；不会把完整后台执行轨迹自动加到主代理对话。
- **控制等待和结果时效**：自动结果有等待上限、turnToken 防止过期结果跨轮使用、待处理自动请求保留最新项、工具请求优先于排队自动查询。

只把这些表述为控制上下文堆积与等待的工程设计，不承诺零 token、必定缓存命中、完全无性能影响或任务效果必然提升。场景导航的前台自动注入仍关闭，不作为已启用的渐进加载功能宣传。

## 当前核验入口

维护网站时先检查这些入口，避免新旧描述重新混用：

- 场景数量与归档：`memory/l2/config.ts`、`archive.ts`、`archive-facts.ts`、`commit-tool.ts`。

- 失败暂停、慢任务与停止：`memory/failure-state.ts`、`memory/pipeline/timeout-config.ts`、`subagent-kill.ts`。

- 技能审查范围与计数：`skill/reviewer.ts`、`feed-cleaner.ts`、`agents/skill-reviewer.md`。
- 数据路径和桥行为：`memory/paths.ts`、`scripts/l1-admin/viewer-bridge.mjs`、`lib.mjs`、`rollback.mjs`。

# Pi Memory 宣传与文档网站设计方案

> 设计日期：2026-10-11。依据：仓库 README、《宣传定位与价值梳理》、现有主图标、中英文宣传视频。
>
> 交付：可浏览的本地设计原型，以及这份信息架构、视觉规则和后续建设说明。原型使用真实框架与组件，交互中的项目内容明确标为示例。

## 1. 网站要帮访问者作出什么判断

访客先看明白“这个扩展对我的持续工作有什么帮助”，随后找到安装和配置路径，使用过程中能回来查说明。

主张：**让每次对话都成为下一次工作的起点。**

首屏标题：**让 Pi 记得项目走到哪里。**

英文标题：**Give your next session a head start.**

主要访客是持续使用 Pi 推进代码项目的开发者。他们熟悉对话助手，但未必理解分层记忆、Embedding 和画像管线。首页从工作结果解释产品，技术细节进入文档。

| 访问阶段 | 要回答的问题 | 页面如何回答 |
| --- | --- | --- |
| 第一眼 | 这是什么？与我有什么关系？ | 一句收益主张，加“两次会话”的具体例子 |
| 想了解 | 它能替我减少什么负担？ | 项目约定、待办进度、工作方法三个可切换示例 |
| 判断可信度 | 我能检查它记住了什么吗？ | 记录管理、画像审阅与当前能力边界 |
| 准备使用 | 怎样装？怎样让召回真正工作？ | 安装入口，独立的 Embedding 与向量化说明 |
| 日常使用 | 状态不对、记录不准时怎么办？ | 可搜索文档，查看器与限制说明 |

## 2. 框架与现成组件

推荐 **VitePress + Vue 3 + Element Plus**。本地原型已经使用这一组合。

| 组成 | 负责什么 | 选择理由 |
| --- | --- | --- |
| VitePress 1.6.4 | 导航、Markdown 文档、目录、页内导航、搜索、中英文路由、静态生成 | 一个站点承载首页和文档；说明内容容易维护 |
| Vue 3.5.43 | 首页场景切换、主题下的共享组件 | 延续现有查看器的 Vue 技术栈 |
| Element Plus 2.14.7 | 按钮、分段选择、标签、页签、折叠问答、视频弹窗 | 控件尺寸、键盘交互和状态由组件库统一 |
| @lucide/vue | 操作与功能图标 | 全站使用同一套线性图标；产品标志继续使用现有主图标 |

VitePress 保留默认文档布局；首页以 Vue 页面组合实现。两者共用颜色、字体和间距令牌。Element Plus 只通过主题变量接入配色，避免在不同区块重新画一套按钮或弹窗。

具体组件：`ElButton`、`ElSegmented`、`ElTag`、`ElTabs`、`ElCollapse`、`ElDialog`、`ElConfigProvider`。文档搜索、移动导航、目录、代码复制、主题切换使用 VitePress 自带组件。

原型保留 VitePress 稳定版，并将其 Vite 依赖固定为 6.4.3；该版本满足当前 Vue 插件的兼容范围。正式升级时一起核对框架、插件和构建结果。

官方依据：[VitePress 主题扩展](https://vitepress.dev/guide/extending-default-theme)、[本地搜索](https://vitepress.dev/reference/default-theme-search)、[国际化](https://vitepress.dev/guide/i18n)、[Element Plus 主题](https://element-plus.org/en-US/guide/theming.html)。

## 3. 视觉方向：清楚的工作台，有延续感的记忆

沿用主图标的绿色与分层形状。首页以浅色为主要展示方向，用深绿色文字、留白和明确的示例形成辨识度；视频区以深绿底提供视觉停顿。深色主题保留同一层级。

最值得记住的视觉是首屏的“两次会话”：上次说过的约定变成记录，在新问题出现时参与回答。它直接对应安装理由，访客可以切换场景理解差异。

### 颜色令牌

| 用途 | 浅色 | 深色 | 规则 |
| --- | --- | --- | --- |
| 页面背景 | `#F8FAF9` | `#141E19` | 保持长文本阅读舒适 |
| 内容表面 | `#FFFFFF` | `#1B2A21` | 示例、记录、弹窗 |
| 辅助表面 | `#EEF4F0` | `#213329` | 流程区、命令片段 |
| 主文字 | `#1A2E24` | `#E5EEE8` | 标题与正文 |
| 次文字 | `#56685E` | `#A2B8AA` | 补充说明，不用于掩盖重要条件 |
| 主操作 | `#247A52` | `#76D5A3` | 深浅主题分别处理按钮前景色 |
| 图标品牌绿 | `#4CC48A` | `#4CC48A` | 保留现有图标，不直接用于浅底小字 |
| 分隔线 | `#DCE5DF` | `#32483A` | 表达内容边界 |

### 字体与尺度

- 字体：Segoe UI Variable / Segoe UI / Microsoft YaHei / 系统 sans-serif，代码使用 Cascadia / Consolas。无需额外字体网络请求。
- 首屏标题：桌面约 59px，手机 39–54px；两行短句，统一颜色。
- 首页章节标题：约 36px，移动端约 26px；内文 14–17px。
- 文档正文：16px，行高 1.8；正文宽度控制在约 700–760px。
- 内容最大宽度：1180px；桌面两侧至少 32px，手机至少 20px。
- 圆角：控件 8px，领域面板 10–12px，首屏与视频容器 18px，按层级区分。

留白、对齐和文字层级负责主要秩序。边框用于会话、记录与数据表等真实分组，绿色用于主要动作和记忆关系。首页不会以大量重复功能卡片承载全部内容。

## 4. 首页结构与文案

```text
共享导航：图标 / Pi Memory / 搜索 / 产品 / 工作方式 / 文档 / 语言 / 主题 / GitHub

┌───────────────────────────┬──────────────────────────────┐
│ 让 Pi 记得                │ 一个项目，两次对话            │
│ 项目走到哪里。            │ [项目约定][待办进度][工作方法]│
│ 用户收益说明              │ 上次会话                      │
│ [开始使用] [观看演示]     │       ↓ 可复用记录            │
│ Windows / Node 条件       │ 下一次会话与接续回答          │
└───────────────────────────┴──────────────────────────────┘

背景少重复 / 经验可再用 / 画像由你确认

对话归档 → 提炼可用信息 → 配置后的相关召回
                 └→ 场景整理 → 画像提议 → 用户确认

[检查与修正] [审阅长期画像] [沉淀工作技能]
左：用户能做什么；右：对应的记录或内容示意

45 秒视频：简短引导 + 宣传视频封面 + 播放弹窗

文档入口：快速开始 / 召回配置 / 查看修正 / 数据与限制
安装命令与复制

安装前问答

最后行动入口：[开始使用] [查看 GitHub]
```

### 首屏

副标题：把对话里的项目事实、工作方法和待办积累下来，在下一次相关工作中按需找回。少一点重复交代，多一点接着往下做。

“开始使用”进入快速开始；“观看 45 秒演示”打开对应语言的视频。两者紧邻，让准备安装和先了解的访客都有清楚路径。

示例使用支付模块：金额单位约定、退款接口待办、支付回调排查方法。点击分段组件后，上次对话、记忆记录、新问题和回答一起变化。必须保留“交互示例 / 配置语义召回后的效果”说明。

### 用户收益

仅保留三个平行结果：项目背景少重复、有用经验再使用、长期画像由用户把关。避免把四个层级名称当作首屏卖点。

### 记忆流程

主路径展示对话、L1 记录和语义召回；另用支线说明场景与画像。这样不会暗示每次召回必须先经过 L2/L3，也不会暗示场景直接进入每轮回答。

### 可控性与技能

三个页签分别展示记录管理、画像提议和技能流程。每个页签都连接对应文档。示意表格统一布局，并明确标为界面或内容示意。

### 视频

使用已有 45 秒中英文宣传视频。按访客当前语言选择影片和封面。静态封面加弹窗播放，视频使用 `preload="none"`；页面打开时不自动播放。

### 文档入口与问答

四个入门链接覆盖安装、召回、查看器和条件边界；命令使用 README 中明确存在的本地目录安装方式。路径是示例，需要替换。

问答说明适合谁、召回配置、数据调用、项目排序、系统限制。兼容条件在首屏也出现，关键设置在对应文档再次说明。

## 5. 文档结构

```text
开始使用
├── 快速开始
├── 记忆如何工作
└── 配置语义召回

日常使用
├── 查看与修正记忆
├── 沉淀可复用技能
└── 限制与数据说明
```

文档桌面采用三栏：左侧分组目录，中间正文，右侧本页导航。每页先说明用户能完成什么，再列步骤、命令、完成标志和必要条件。

中英文路径对应：`/docs/*` 与 `/en/docs/*`。导航、搜索文案、首页交互、问答和视频语言随之切换。

本地搜索覆盖 Markdown 说明，按标题和正文查找。原型已提供中英文各六页；完整 API、参数参考、排错手册和版本更新记录作为正式建设的后续内容。

## 6. 手机与交互规则

- 手机首屏改为单列：主张和按钮在上，交互示例在下；示例的三个选项仍能直接切换。
- 工作流程在窄屏改为纵向；文档入口改单列。记录表格保持可读的三列简表。
- 文档使用框架自带的移动目录和导航。
- 主题覆盖背景、正文、次文字、分隔线、记录表、组件、弹窗和问答。
- 使用现成组件的键盘焦点、展开状态和弹窗行为。视频关闭后销毁内容。
- 复制命令后显示“已复制”，失败时说明可以手动选择；不伪报成功。
- 尊重系统减少动态效果设置。初版不依赖持续自动动画，让访客主动操作示例。

## 7. 宣传事实与边界

| 可以表达 | 必须同时理解的条件 |
| --- | --- |
| 在后台积累可用记忆 | 提取有触发条件，受模型、队列和配置影响 |
| 按问题找回相关记录 | Embedding 与向量化需要配置，历史记录需回填，不保证每次命中 |
| 记忆可检查、可修正 | 通过本地查看器和扩展命令操作 |
| 画像由用户确认 | 提议不自动覆盖正式画像，新会话读取正式背景 |
| 从流程中学习技能 | 有复用与质量门控，不是每段对话都能生成 |
| 记忆文件保存在本地 profile | 模型与 Embedding 调用的数据去向由配置决定 |

不编造用户数量、客户 Logo、好评、准确率、节省时间比例或性能数据。示例与真实截图都标明来源；正式建站时可补入经过筛选的实际查看器截图。

“限制与数据说明”收录当前 chat 模式类型冲突、查看器桥鉴权缺失、长操作阻塞和 skill-feed 脱敏边界，并注明静态核对的日期与方法。

## 8. 原型位置与运行

```powershell
cd C:\dev\code\pi-extension\pi-memory-system\website
npm install
npm run dev
```

本地地址：`http://127.0.0.1:5188/`；英文版：`http://127.0.0.1:5188/en/`。

```powershell
npm run build
npm run preview
```

`scripts/sync-assets.mjs` 在启动和构建前从仓库同步图标、视频和封面到忽略的生成目录；正式素材仍以仓库 `assets/` 为准。原型不连接个人记忆库，所有演示记录为明确标注的说明内容。

## 9. 后续正式建设

当前方案可以直接作为正式网站的结构基础。下一阶段先落实完整安装来源与发布状态，然后扩充配置参考、命令索引和常见排错；将示意图补充为有来源的实际产品截图。

公开发布时再配置域名、站点 base 路径、canonical URL、sitemap 和分享卡片，并按实际渠道验证部署。网站依赖放在独立 `website/package.json`，不进入插件运行依赖。

# 查看与修正记忆

本地查看器把记忆库、场景、画像提议和任务队列摊开，让你能检查和纠正系统自动整理的结果。

## 打开

```powershell
npm run viewer
```

Windows 也可以双击 `viewers/启动查看器.cmd`。启动器会同步最新页面、找一个空闲端口（默认从 5174 开始）、拉起本地桥并打开浏览器。

直接双击 HTML 文件打不开数据——页面需要桥提供接口。查看器默认读取当前激活的 profile，也可以用 `--profile` 指定。

::: warning 本机使用
桥默认只监听回环地址，没有鉴权，CORS 允许任意来源。开启 `--lan` 会扩大到局域网。详细边界见[数据、隐私与备份](./data)。
:::

## 五个页面

| 页面 | 看什么 | 能做什么 |
| --- | --- | --- |
| 总览 | 数据健康、页面版本 | 只读 |
| L1 记录 | 记忆正文、来源、质量分、项目标签、任务状态 | 改写、作废、改任务状态、补齐向量、还原备份 |
| L2 场景 | 场景块、成员清单、归档区 | 归档、恢复、场景池报告 |
| L3 画像 | 正式画像、提议稿、差异 | 编辑提议稿、并入、还原备份 |
| 流水线 | 排队、运行、最近结束的作业、待处理触发信号 | 请求入队、停止子代理 |

## 修正一条记录

记录内容不对时，有两个层面的修改：

| 你想做什么 | 用哪个 | 会不会改正文 |
| --- | --- | --- |
| 改错别字或表述 | 改写（rewrite） | 会，生成新版本 |
| 这条记录根本不成立 | 作废（tombstone） | 不改，只打删除标记 |
| 这件事做完了 | 任务状态改成 `done` | 不改 |
| 这件事不做了 | 任务状态改成 `dropped` | 不改 |

改写有三道保护：

- **需要可复核证据**，至少 20 字符。写清"为什么改"，不是写"改一下"。
- **24 小时防抖**：同一条记录在 24 小时内不能重复改写。
- **高价值保护**：命中次数达到 5 次，或被场景收录为成员时，拒绝自动改写，需要显式绕过。

这些限制不是防用户，是防止模型在自动化流程里反复改同一条记忆。

::: danger 改写不是编辑
改写会生成新版本、把旧版本标为删除。原正文仍留在分片里供溯源，但它在召回和 L2 里都不再出现。想保留可逆性时，优先用任务状态而不是作废。
:::

## 审阅画像提议

L3 生成的提议在 `USER-temp.md`。查看器会把正式画像和提议稿并排显示差异。

并入前先想清楚三种操作的区别：

| 操作 | 结果 |
| --- | --- |
| 追加并入（默认） | 保留正式画像现有条目，补充提议稿里没有的 |
| 编辑提议稿后并入 | 按你改后的文本追加 |
| 完整替换 | 用提议稿整体覆盖正式画像 |

默认追加策略有一个副作用：如果你把某条提议改写成新表述，旧条目不会被删除，两条会同时存在。看到矛盾的表述时需要手动整理。

正式画像的变化**下一次新会话**才生效。当前会话用的是启动时的快照。

## 处理流水线

流水线页显示三层任务的排队、运行和最近结束状态，以及等待消费的触发信号。

::: info "请求入队"不等于立即执行
查看器写下一份触发信号，需要 Pi 主会话在活动结束时消费它。只开查看器不会自己跑后台模型。

信号躺在盘上的原因通常是：Pi 会话没有活动、对应的 profile 不是当前激活项，或者该层正被熔断。
:::

停止子代理时优先用这个页面或命令，不要手动删运行锁目录。停机流程会先拦写、再给收尾时间、再杀进程、最后修复半写文件。

## 长操作会阻塞

查看器桥用同步方式调用命令行工具。向量补齐、向量重建、整库还原这类操作执行期间，其他请求会等它结束。

操作没返回时不要假定已经完成，也不要在执行期间开第二个窗口重复点。

## 页面更新

查看器页面是部署副本，放在 `memoryDB/viewers/`。扩展升级或修改页面源码后，扩展会重新部署这些副本。页面与记忆记录分开存放，删掉副本不影响数据。

如果页面看起来是旧版，先确认扩展已重新加载，再检查 `viewer-manifest.json` 的版本。

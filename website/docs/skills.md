# 沉淀可复用技能

有些经验适合保存成事实，有些经验适合成为步骤清楚的操作指南。技能学习面向后者。

## 什么适合成为技能

比如一套反复有效的故障排查流程、一个明确的验证步骤，或一个可重复的操作方法。它应有适用条件、输入、步骤和结束标准。

“我喜欢先讨论方案”属于偏好；“如何排查支付回调”可以是技能。个人偏好和执行流程分开管理。

## 主动发起学习

在 Pi 中使用：

```text
/learn
```

也可以用 `/learn [source]` 指定源码、文档或讨论材料。扩展还会周期性审查增量 skill-feed。

周期审查默认累计 20 次交互输入后检查，审查期间暂停计数，并等待完整助手回复作为材料。当前增量审查使用本会话的 feed，不会自动补学所有历史会话。它独立于 L1–L3 串行队列。

## 学习后看什么

比如一次回调排查，单次问题的原因可以保存成事实，可迁移的判断原则可以保存成方法；如果形成了有输入、步骤、分支、输出和验证标准的完整流程，则适合整理为技能。

审查会优先更新或补充已有同类技能，再考虑新建。生成后检查触发条件、必要输入、失败分支和验证步骤；“请求已提交”不表示一定创建了新技能。质量门控由提示词指导模型执行，仍可能判断失误。

## 技能的来源与边界

skill-feed 保留工具调用与结果，帮助审查执行步骤；它不同于 L0 的普通正文归档。提取有复用条件和质量门控，并非每次对话都会生成技能。

默认清洗不等于通用凭据脱敏。工具参数与结果若包含秘密信息，可能进入 skill-feed 并用于配置模型的技能审查。阅读[数据、隐私与备份](./data)后决定适合放入的材料。

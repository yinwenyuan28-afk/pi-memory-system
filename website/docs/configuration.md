# 配置说明

先用 `/my-memory:model` 配置模型与向量化，再用 `/my-memory:model:peek` 检查状态。若希望按问题语义找回相关记忆，推荐配置 Embedding 服务并开启向量化。阿里云百炼是作者正在使用的服务之一；其部分文本向量模型目前列有免费额度，具体适用条件和额度以[官方文档](https://docs.bailian.console.aliyun.com/zh/model-studio/embedding)及控制台为准。通常不需要修改源码；理解下面几组配置，能解释为什么“记忆已经保存”却还没有按问题召回。

## 配置在哪里

当前记忆空间的配置文件是：

```text
<agentDir>/profiles/<profile>/memoryDB/config/application-propertis.json
```

文件名中的 `propertis` 是当前实际拼写。文件支持 `//` 注释，属于 JSONC。不同 profile 使用各自配置。手工改配置时保留已有节，修改后重启 Pi，使主进程和后台进程使用一致配置。

## 两类模型各做什么

| 设置 | 用途 | 默认或注意事项 |
| --- | --- | --- |
| `model.llm` | 后台记忆处理的模型 | 未指定时跟随前台模型；选择它不会切换当前对话模型 |
| `model.embedding` | 把记录和查询转换成向量 | 需要配置服务地址、密钥、模型与维度 |
| `vectorization` | 控制新提交记录的自动向量化 | 默认关闭，与 Embedding 连接配置分开 |

配置 Embedding、开启自动向量化、达到自动阈值、补齐历史向量是不同动作。默认自动阈值是最近 365 天 **500 条有效 L1 记录**。历史回填使用单独命令，详见[配置语义召回](./recall)。

::: tip 首次配置建议
启用开关不会立即为所有旧记录建立向量。记录数量较少时，可以运行 `/my-memory:l1:embedding:backfill` 手动回填，以便尽早体验语义召回。使用远端 Embedding 服务前，请确认记忆内容可以发送到对应服务；详见[数据、隐私与备份](./data)。
:::

::: warning 更换 Embedding 模型
不同模型的向量不能直接混用，维度相同也不代表兼容。已有向量表时，向导会阻止不兼容的维度修改，但不会迁移旧向量。更换服务或模型前先备份，并规划全量重建。
:::

## 召回设置

| `recall` 字段 | 默认值 | 用户可见效果 |
| --- | --- | --- |
| `minScore` | `0.2` | 用原始余弦相似度筛掉低相关候选；提高可能减少命中 |
| `maxCharsPerRecord` | `300` | 单条召回正文的字符上限，超长截断 |
| `maxTotalChars` | `2000` | 召回正文总字符预算，超出停止追加 |
| `contextExpansion` | `conditional` | 较短或含指代的输入可结合最近用户消息构造查询 |
| `injectMode` | `blocking` | 本轮先等待召回；`async` 表示先放行回答，再在后续上下文组装时补入 |
| `injectTimeoutMs` | `1000` | 自动召回初始等待上限，单位毫秒 |
| `hideClosedTasks` | `false` | 默认仍召回完成或废弃任务，并附状态；设为 `true` 时排除它们 |

自动注入最多 3 条，主动工具查询默认 5 条。这两个数量目前是源码阈值，不是 JSONC 中的可配置字段。

例如，希望隐藏已关闭任务，可以在已有 `recall` 节中设置：

```jsonc
"hideClosedTasks": true
```

这是一个字段片段，需要放入现有 JSONC 对象中，不能单独替换整个配置文件。其他字段维持当前值即可。

## 记忆整理与任务时限

| 设置 | 默认值 | 含义 |
| --- | --- | --- |
| `l1.mode` | `code` | 提取开发工作的事实、待办、方法与资产 |
| `l1.valueCheck.enabled` | `true` | 后台提交前复核候选的保存价值；不用于主代理直接保存 |
| `l2.maxScenes` | `15` | 活跃场景文件数量上限 |
| `subagent.softMs` | `630000` | 只记录慢任务日志，继续等待 |
| `subagent.hardMs` | `1800000` | 到点进入停止流程 |

当前 `chat` 模式有类型契约缺陷，详情见[限制与数据说明](./limits)。不要因为任务运行时间长就立即压低硬上限，先用日志区分模型慢、网络失败和未成功提交。

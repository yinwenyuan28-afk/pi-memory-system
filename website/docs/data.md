# 数据、隐私与备份

记忆文件保存在本地 Pi profile 中。后台模型处理和向量化可能向配置的服务发送内容，实际处理位置取决于你选用的模型服务。

## 各类数据保存在哪里

下面的路径都相对于当前 `<agentDir>/profiles/<profile>/`。多数文件按需生成，因此新空间可能还没有全部目录。

| 路径 | 内容 |
| --- | --- |
| `MEMORY.md`、`USER.md` | 正式背景文件，新会话读取快照 |
| `USER-temp.md` | 等待审阅的画像提议稿 |
| `memoryDB/l0/conversations/` | 按日期归档的用户与助手正文 |
| `memoryDB/l1/records/` | 原子记忆 JSONL 分片 |
| `memoryDB/l1/scenes.json` | 稳定场景编号和标签 |
| `memoryDB/l2/scene-blocks/`、`memoryDB/l2/index/` | 活跃场景、索引和成员清单 |
| `memoryDB/l2/archive/` | 已归档场景、成员和操作账 |
| `memoryDB/skill/feed/` | 技能学习的独立输入 |
| `memoryDB/search/vectors/` | L1 本地向量数据库 |
| `memoryDB/pipeline/`、`memoryDB/state/` | 作业、进度相关运行状态和失败状态 |
| `memoryDB/config/` | 模型、向量化及整理配置，可能包含密钥 |
| `memoryDB/logs/`、`memoryDB/backups/` | 运行日志和部分操作的备份 |
| `state/review-cursor.json` | 技能审查处理进度 |

查看器页面是部署副本，保存在 `memoryDB/viewers/`。修改页面源码或安装新版本时，这些副本会同步；它们与真正的记忆记录分开。

自动召回块只插入模型调用前的消息副本，不写入主会话 JSONL。这不影响 L0、L1 自身的持久保存；主动工具查询和助手回答也仍可进入会话历史。详细边界见[上下文与渐进式设计](./context-design)。

## 哪些内容可能交给模型

| 操作 | 模型或服务可能接收的内容 |
| --- | --- |
| L1 提取、去重与价值复核 | 归档正文、候选记忆、相关旧记录及任务资料 |
| L2 整理 | 新记忆和有关的已有场景 |
| L3 提议 | 正式画像、提议稿、相关场景 |
| 项目判定 | 会话中提取的路径证据与判定资料 |
| Embedding 写入和查询 | 需要建立向量的记忆正文、加工后的问题查询 |
| 技能审查 | 当前会话的增量 skill-feed，含工具参数与结果 |
| 前台回答 | 当前 Pi 模型收到的正式背景快照和召回记忆 |

这张表说明主要数据路径，具体输入仍以当前实现和任务为准。选择远端服务时，这些输入可能离开设备；使用本地服务也要确认所有实际调用采用了对应配置。

## 内容净化的边界

L0 清理框架噪音并只保留用户与助手正文；普通提取不会读取工具调用和结果。技能学习为了理解执行过程，另用保留工具记录的 skill-feed。两条输入通道有独立进度。

默认净化不保证识别所有 API Key、密码或 Bearer token。长度截断也不等于脱敏；秘密可能已经出现在正文、工具参数、结果、日志或备份中。处理敏感材料前先检查会话内容与服务设置。

## 本地查看器的访问边界

桥默认只监听本机回环，手动启动后才运行。当前没有鉴权，CORS 允许任意来源；浏览器对本机请求的权限限制可能不同，不能把回环监听当成完整访问保护。

显式启用 `--lan` 或 `--host` 会扩大网络访问范围，可访问者可能读取记忆并调用写操作。配置目录被排除在静态托管之外，但记忆正文自身仍可能包含敏感内容。只在可信环境启用，用完关闭桥。

## 怎样备份

需要保留整个记忆空间时，备份完整 profile 目录，包含根目录画像文件、`memoryDB`、成员清单与审查状态。只保存 L1 分片无法恢复完整场景和画像关系。

先让运行中的任务结束，再关闭使用该空间的 Pi 进程和查看器桥，确认没有后台子代理仍写入，然后复制目录。运行时直接复制 SQLite 文件可能漏掉尚在日志文件中的写入，或得到不同时间点的数据。

profile 配置可能包含密钥，备份应按私人资料保管。profile 之外的宿主会话、共享技能和宿主设置需要按需另外备份。

## 删除和还原的范围

| 操作 | 实际含义 |
| --- | --- |
| 关闭任务 | 保留记忆，只改变待办状态 |
| 删除 L1 记录 | 标记作废，原正文仍可能留在分片中供溯源 |
| 归档场景 | 搬到归档区，仍可恢复 |
| 还原 L1 备份 | 用备份替换当前 L1 分片集合，会影响备份之后的记录 |
| 还原画像提议 | 恢复提议稿，区别于修改正式画像 |
| 重建向量 | 清空旧向量并重新嵌入有效记录，不重建丢失的原始记忆 |

“删除”不是从所有归档、来源会话、日志和备份中彻底抹除，也不会撤销服务商已经收到的数据。还原前检查界面所标明的对象和范围，并另存当前数据。

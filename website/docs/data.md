# 数据、隐私与备份

记忆数据全部保存在本地 profile 目录。但"本地保存"不等于"内容从不离开设备"：后台整理和向量化都会把内容发给配置的模型或 Embedding 服务。

## 数据在哪

路径相对于 `<agentDir>/profiles/<profile>/`：

| 路径 | 内容 | 生成时机 |
| --- | --- | --- |
| `MEMORY.md` | 正式长期背景 | 首次运行创建空文件；当前没有程序写入路径，靠人工维护 |
| `USER.md` | 正式用户画像 | 首次运行创建空文件；由你在查看器确认并入提议稿时更新 |
| `USER-temp.md` | 画像提议稿 | L3 运行后 |
| `memoryDB/l0/conversations/*.jsonl` | 净化后的对话正文 | 每轮活动结束 |
| `memoryDB/l0/cursor.json` | 每个会话的归档行号 | 归档后 |
| `memoryDB/l1/records/*.jsonl` | 原子记忆 | L1 提交或主代理主动保存 |
| `memoryDB/l1/cursor.json` | L1 消费到哪个字节 | L1 提交 |
| `memoryDB/l1/scenes.json` | 场景池 | L1 提交时新建或复用场景 |
| `memoryDB/l1/hit-stats.sqlite` | 命中统计 | 记忆真正被注入或工具召回时 |
| `memoryDB/l1/value-check-log.jsonl` | 价值复核淘汰记录 | 复核判为丢弃时 |
| `memoryDB/l2/scene-blocks/*.md` | 场景正文 | L2 提交 |
| `memoryDB/l2/index/scene_members.json` | 场景包含哪些记录 | L2 提交 |
| `memoryDB/l2/index/scene_index.json` | 场景索引 | 每次 L2 提交后重建 |
| `memoryDB/l2/archive/` | 归档场景、成员、操作账 | 归档操作 |
| `memoryDB/l3/cursor.json` | 画像处理进度 | L3 提交 |
| `memoryDB/search/vectors/l1-vectors.sqlite` | 向量索引 | 记录提交且向量化可用时 |
| `memoryDB/pipeline/jobs.sqlite` | 任务队列 | 每次入队与状态变化 |
| `memoryDB/state/failure-state.json` | 失败计数、层持有 | 失败或停止时 |
| `memoryDB/config/application-propertis.json` | 统一配置，含密钥 | 首次配置时 |
| `memoryDB/logs/` | 按范围分文件的日志 | 持续写入 |
| `memoryDB/subagent-sessions/` | 后台子代理的会话文件 | 每次派发 |
| `state/review-cursor.json` | 技能审查进度 | 审查完成后 |

多数目录按需创建，新空间不会一开始就全都有。配置文件名的 `propertis` 是实际拼写，不是笔误。

## 哪些内容会离开设备

| 操作 | 接收方 | 可能包含的内容 |
| --- | --- | --- |
| L1 提取 | 后台 LLM | L0 对话正文、候选记忆、相似旧记录 |
| L2 整理 | 后台 LLM | 新记忆、相关场景正文 |
| L3 画像 | 后台 LLM | 正式画像、提议稿、变化场景摘要 |
| 项目判定 | 后台 LLM | 会话中出现的路径与相关片段 |
| 向量化写入 | Embedding 服务 | 记忆正文 |
| 向量化查询 | Embedding 服务 | 构造后的查询文本 |
| 技能审查 | 后台 LLM | skill-feed 增量，含工具参数与结果 |
| 前台回答 | Pi 当前模型 | 正式背景快照 + 本轮召回记录 |

选择远端服务时，这些内容都会离开设备。使用本地服务也要确认所有实际调用都走了同一份配置，包括后台 LLM、Embedding 和前台模型。

::: warning 净化不等于脱敏
内置净化规则处理的是框架噪音、图片编码、空内容和斜杠命令。它**不保证**识别 API Key、密码、Bearer token 或其他凭据。

长度截断也不等于脱敏。秘密可能已经出现在正文、工具参数、工具结果、日志或备份里。
:::

## 两条输入通道的区别

| 通道 | 保留什么 | 用途 | 进度文件 |
| --- | --- | --- | --- |
| L0 归档 | 只保留用户与助手正文 | L1 提取 | `l0/cursor.json` |
| skill-feed | 用户、助手、工具调用、工具结果 | 技能审查 | `skill/cursor.json` |

普通归档丢掉工具调用和结果，是因为 L1 要的是结论和经验：用户需求通常在工具调用前，助手的判断和结论通常在工具调用后，中间过程可以省略。

技能学习需要工具记录，因为要理解"做了什么操作、拿到什么结果"。这也意味着 skill-feed 里可能包含命令参数、文件内容、接口响应，检查私密内容时不能只看 L0。

两条通道的进度相互独立：一条慢或失败，不影响另一条。

## 查看器的访问边界

```powershell
npm run viewer
```

默认从 5174 开始，端口被占用时自动向后找。

::: danger 默认没有鉴权
桥只监听本机回环地址，没有访问令牌，CORS 允许任意来源。浏览器对本机请求的权限限制因浏览器和配置而异，不能把"监听 127.0.0.1"当成完整的访问保护。

显式启用 `--lan` 或 `--host` 会扩大访问范围：能访问的人可以读取记忆，也可以调用部分写操作。只在可信网络里临时使用，用完关闭。
:::

查看器页面本身是部署副本，放在 `memoryDB/viewers/`。它和记忆记录分开，删掉副本不影响数据；扩展更新后会自动重新部署。

## 怎样备份

需要保留整个记忆空间时，复制完整 profile 目录：

```text
<agentDir>/profiles/<profile>/
├── MEMORY.md
├── USER.md
├── USER-temp.md
├── memoryDB/
└── state/
```

只备份 `l1/records/` 无法恢复场景和画像关系：场景正文在 `l2/`，成员清单在 `l2/index/`，画像提议在 profile 根目录。

备份前的顺序很重要：

1. 让运行中的任务结束，或至少确认没有子代理在写。
2. 关闭使用该空间的 Pi 进程和查看器桥。
3. 再复制目录。

运行时直接复制 SQLite 文件可能漏掉还在 WAL 日志里、尚未合并的写入，也可能拿到不同时间点的数据。

profile 配置可能包含 API Key，备份应当作私人资料保管。

## 删除和还原的真实范围

| 操作 | 实际含义 | 能回退吗 |
| --- | --- | --- |
| 关闭任务 | 只改 `taskState`，正文与编号不变 | 能，`reopen` |
| 删除 L1 记录 | 就地标 `deleted`，正文仍留在分片里 | 不能，只能重新提交 |
| 归档场景 | 搬到 `l2/archive/`，正文与成员都保留 | 能，`restore` |
| 还原 L1 备份 | 用备份替换当前分片集合 | 会丢掉备份之后的新记录 |
| 还原画像提议 | 恢复 `USER-temp.md` | 不影响正式画像 |
| 重建向量 | 清空向量库重新嵌入存活记录 | 不重建丢失的原始记忆 |

"删除"不是从所有归档、来源会话、日志和备份中彻底抹除，也不会撤销模型服务已经收到的内容。操作前先看清界面标注的对象和范围，并另存当前数据。

# 限制与已知问题

这一页只写能核实的边界。分三类：环境要求、能力边界、已知缺陷。

## 环境要求

| 项 | 要求 | 原因 |
| --- | --- | --- |
| 系统 | Windows | 停止子代理依赖 Windows 进程树语义；项目路径判定按盘符规则 |
| Node.js | ≥ 22.13.0 | 扩展 `engines` 下限 |
| Pi | 0.83.0+ | 该版本要求 Node ≥ 22.19，两者取高；实测组合见 README |

macOS 与 Linux 没有验证过，不是"应该能跑"，而是"没有适配"。

## 能力边界

| 主题 | 当前边界 |
| --- | --- |
| 提取质量 | 依赖所配模型的判断，不保证每条都值得留 |
| 召回效果 | 受相关性、条数、字符预算和时序限制，可能为空 |
| 项目归属 | 只影响排序，不做隔离；可能判成 `unknown` |
| 场景注入 | L2 场景不进入每轮回答 |
| 画像生效 | 必须人工确认，且新会话才读取 |
| 数据同步 | 无跨设备同步，备份靠复制目录 |
| 语言 | 界面中英双语；提取内容的语言跟随源对话 |

## 已知缺陷

以下都在当前源码中可核实，不是推测。

### chat 提取模式不可用

`l1.mode` 可以设成 `chat`，提示词也会按对话场景提取 `persona` / `episodic` / `instruction`。但提交端只接受 `work_fact` / `work_task` / `work_method` / `work_artifact` 四类。

结果：`chat` 模式产出的记录会被格式检查拒绝，整批提交失败。

**规避**：保持默认的 `code` 模式。

### 命令行工具没有提交写锁

`scripts/l1-admin/` 下的 `.mjs` 写操作（`tombstone.mjs`、`rewrite.mjs`）会检查**运行锁**，确认没有子代理正在写这一层。但它们没有使用提交级写锁。

`task-state.mts` 是例外：它转发到 `memory/l1/task-state.ts` 的同一个实现，内部会取提交写锁。所以任务状态标记是安全的，问题只在正文改写和作废这两条路径。

**影响**：如果子代理恰好在提交时段，两边的读-改-写可能交错。概率低，但存在。

**规避**：手工改写前确认流水线没有运行中的任务。

### 活跃日时钟是全局的

质量衰减按"有归档的日历天"计算，不区分项目。

**影响**：长期并行多个项目时，某个项目停止但其他项目仍活跃，该项目的记忆会继续衰减。

**规避**：无。判断淘汰候选时结合项目标签一起看。

### 查看器桥没有鉴权

默认只监听回环，但 CORS 允许任意来源，也没有访问令牌。

**影响**：局域网模式下，同网段任何设备可以读取记忆并发起写操作。

**规避**：只在可信网络临时开启，用完关闭。

### 长操作会阻塞查看器

桥用同步方式调用 CLI。向量补齐、重建、整库还原执行期间，其他请求排队。

**规避**：一次只跑一个长操作，等它返回再点别的。

### 场景池写入失败不回滚

场景池 `l1/scenes.json` 在记录写入磁盘之后写回。写入失败时记录已经带着解析后的场景名写入磁盘，池里可能缺这个条目。

**影响**：下一批可能重建同名条目，不丢数据，但可能出现短暂的条目不一致。

**规避**：无。日志里会记 `scenePool.writeFailed`。

### 净化不识别凭据

内置规则处理框架噪音和图片编码，不做通用凭据识别。API Key、密码、token 可能留在 L0、skill-feed、日志和备份里。

**规避**：处理敏感材料前先检查内容，不要把密钥贴进对话。

## 效果上的现实预期

这些不是缺陷，但容易被误解：

| 期待 | 实际情况 |
| --- | --- |
| "记下所有重要内容" | 模型判断有波动，漏记和误记都可能发生 |
| "问一句话就想起所有相关记忆" | 受阈值、条数、预算限制，空结果正常 |
| "同一件事永远归到同一个场景" | 场景复用靠模型举证，仍可能分裂 |
| "画像会自动变得越来越准" | 需要你确认并入，不确认就不生效 |
| "装了扩展就更快" | 每轮召回最多增加 1 秒延迟，后台任务消耗模型调用 |

## 怎么判断问题出在哪

| 现象 | 先查 |
| --- | --- |
| 完全没有记录 | L0 是否归档（`l0/conversations/` 有没有当天文件） |
| 有归档没记录 | L1 是否入队、是否熔断、日志里的失败原因 |
| 有记录召回不到 | 有没有向量、阈值是否过高、是否超时 |
| 任务一直排队 | 是否有别层在跑、该层是否被熔断或持有 |
| 子代理跑很久没结束 | 看日志区分模型慢、网络失败、提交未成功 |
| 查看器打不开 | 端口占用、桥是否启动、profile 是否正确 |

完整排查步骤见[后台流水线](./pipeline)和[召回与注入](./recall)。

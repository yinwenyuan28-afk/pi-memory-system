# 限制与数据说明

以下基于 2026-10-11 的仓库说明与功能梳理。了解这些条件，能帮助你判断插件是否适合自己的工作方式。

## 环境与效果条件

| 主题 | 当前边界 |
| --- | --- |
| 系统 | 当前仅支持 Windows；需要 Node ≥ 22.13 |
| 语义召回 | Embedding 服务需要配置；向量化默认关闭，默认自动阈值 500 条有效记录；历史记录需回填 |
| 召回效果 | 受相关性、数量、字符预算和时序约束；不保证所有信息都被提取或命中 |
| 多项目 | 项目归属影响排序，不是严格隔离；归属可能为 unknown |
| 场景 | L2 当前不自动注入每轮回答 |
| 画像 | 提议先写入 USER-temp.md，需要用户审阅并入 |

## 文件位置与外部调用

记忆文件保存在 Pi profile。后台提取和技能审查使用配置的模型，向量化使用配置的 Embedding 服务。实际数据处理位置由你的服务配置决定。

默认内容净化不保证移除所有 API Key、密码或 Bearer token。skill-feed 可保留工具参数和工具结果，需要特别留意其中的秘密信息。

## 当前已记录的问题

- **chat 提取模式：** 提示词类型与提交端枚举不一致，可能导致记录提交失败。当前以开发工作记录为主要设计展示场景。
- **查看器桥：** 没有鉴权，CORS 允许任意来源。默认回环监听也不等于具备访问令牌保护；LAN 模式扩大访问范围。
- **长操作：** 查看器桥同步执行 CLI，向量回填与重建等任务可能阻塞其他请求。
- **秘密信息清洗：** skill-feed 默认清洗没有通用凭据脱敏保证。

这些是功能梳理中的静态核对结果，不代表已完成实时模型复现。最新状态应以仓库源码、README 和问题修复记录为准。

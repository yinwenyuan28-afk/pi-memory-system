# 快速开始

Pi Memory 将 Pi 对话中的有效信息提炼成记忆，帮助你在后续会话中继续项目工作。先完成安装，再按需要配置语义召回。

::: info 当前兼容条件
当前仅支持 **Windows**，需要 **Node ≥ 22.13**。项目实测宿主组合为 Pi 0.84.2、pi-coding-agent 0.83.0、pi-ai 0.74.2；这组版本是验证记录，不是所有兼容版本的列表。
:::

## 安装扩展

准备好插件目录后，在终端按本地目录安装。将示例路径换成你实际使用的路径。

```powershell
pi install ./path/to/memory-system
```

安装完成后，在 **Pi 会话**中执行：

```text
/reload
```

也可以重启 Pi。后台子代理由本扩展启动，无需安装 pi-subagents。

::: warning 只选择一种安装方式
不要同时保留扩展扫描目录中的副本和 packages 包安装，否则可能重复加载、注册同名工具。`pi install` 不接受 `.tgz` 文件作为扩展目录；压缩包需要先解包。
:::

## 检查模型配置

在 Pi 中执行只读检查命令：

```text
/my-memory:model:peek
```

它显示后台模型来源、Embedding 配置状态、向量化开关、阈值和向量数，不会显示 API Key，也不会请求远端。

后台提取默认跟随前台模型。L1 默认在累计 10 次交互输入后安排后台提取，处理受队列、模型和配置影响。

## 进行一次小规模检查

在一个持续项目中讨论明确的事实或待办。例如，在正常工作中说明项目路径、已确认的幂等键，以及需要补充的重试测试。完成回复后，按需要手动请求提取：

```text
/my-memory:l1-trigger
```

这会安排后台工作，完成后可在[本地查看器](./viewer)检查记录与流水线状态。不要把“请求已提交”当作“提取已经完成”。

先确认 L1 记录是否保存、内容和来源是否正确；建立向量后，再用相关问题检查召回。提取、向量化和召回分别检查，能更快定位问题。若不知道某一步为什么没发生，阅读[后台运行与故障恢复](./pipeline)。

## 配置下一次召回

如果希望按当前问题的含义检索相关记录，推荐继续阅读[配置语义召回](./recall)，配置 Embedding 服务并开启向量化。向量化默认关闭，安装本身不会自动完成 Embedding 配置；普通记忆提取和保存仍可使用。已有少量记录时，可手动回填向量。作者使用的阿里云百炼为部分文本向量模型提供免费额度，资格和有效期请以控制台为准。

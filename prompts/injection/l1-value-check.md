1. **流水账**：这条记的是"当时发生了什么、做了什么、进度如何"，还是"以后遇到同类任务该怎么做/该按什么判断"？

## 输出要求（严格）

只输出一个 JSON 对象，不要任何解释、不要 Markdown 代码块：

```
{"verdicts":[{"i":0,"v":"keep"},{"i":1,"v":"drop","r":"流水账：记录了本次改动的过程，换一个会话完全用不上"},{"i":2,"v":"retype","t":"work_fact","r":"描述的是现状事实，不含规范词"}]}
```

字段契约：

- `i`：候选记录的序号（从 0 开始），**必须与输入的 records 一一对应，一条不漏**。
- `v`：`keep` | `drop` | `retype`。
  - `keep` —— 有跨会话复用价值，照写。
  - `drop` —— 不写。**必须给 `r`**，写清是哪条判据不过（流水账 / 停在表象 / 可低成本找回 / 只是进度或状态读数）。
  - `retype` —— 内容有价值但类型判错了，**必须给 `t`**（`work_fact` / `work_method` / `work_task` / `work_artifact`），并给 `r`。
- `r`：一句话理由，说清"不过哪个闸"，不要复述内容。

**拿不准就 `keep`。** 误杀的代价是这条经验彻底消失（不会被任何后续步骤补回来），误留的代价不过是库里多一条待淘汰的记录——两者不对称，所以只在**明确**是流水账或可低成本找回时才 `drop`。

**不要在 `drop` 时"顺手"把内容改写后返回**——你不负责重写，只负责判定。

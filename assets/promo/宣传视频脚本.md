# pi-memory-system 中文宣传视频

主张：**让每次对话，都成为下一次工作的起点。**

依据：[宣传定位与价值梳理.md](../../宣传定位与价值梳理.md)。参考旧片的深绿、薄荷色、记忆卡片与新会话召回表达，重新组织叙事。

规格：45 秒，1920 × 1080，16:9，30 fps；中文合成女声、内嵌中文字幕、原创程序合成背景音乐。H.264 视频与 AAC 音频，适合网页播放。

## 分镜与旁白

| 时间 | 画面 | 中文旁白 |
|---|---|---|
| 00–05 秒 | 左侧提出“昨天刚说清，今天又要重来？”；右侧依次出现项目背景、排序决定、回归待办 | 每次继续一个项目，都要重新交代背景、决定和下一步？ |
| 05–12 秒 | 昨天的订单项目对话，经后台处理，提炼为事实、方法、待办与成果四张卡片 | Pi 记忆系统，把对话里的事实、方法、待办和成果，整理成可复用记忆。 |
| 12–18 秒 | 相关记忆汇入“订单列表 · 稳定排序修复”场景，以发现、决定、下一步串起经历 | 相关记录逐步汇成工作场景，保留项目的来龙去脉。 |
| 18–27 秒 | 第二天打开新会话，用户问接下来做什么；相关方法与待办出现，进入回答上下文，再显示延续工作的回答 | 配置好语义召回，在新会话继续工作时，Pi 可以找回相关经验，接着往下做。 |
| 27–34 秒 | 查看器操作示意：查看来源、修正内容、删除记录；鼠标将回归用例从待办标记为已完成 | 待办、已完成，状态清楚。记忆也能检查和修正。 |
| 34–40 秒 | 画像提议稿与正式画像并列；选择条目，再确认并入，正式画像才出现新条目 | 长期画像先提出建议，由你审阅，确认后再生效。 |
| 40–45 秒 | 品牌图标、主张、产品名与“查看项目与安装说明”出现，附项目地址 | 让每次对话，都成为下一次工作的起点。 |

## 宣传边界

- 画面均为产品流程动画与示例数据，非真实运行录屏；视频右上角持续标注。
- 按代码模式的四种工作记忆类型演示，没有宣传当前存在类型契约缺陷的 chat 模式。
- 提取镜头注明按后台阈值执行，也支持手动触发，没有承诺每句话立即生成记忆。
- 场景镜头注明场景用于组织与后续处理，当前不自动注入每轮前台问答。
- 召回镜头注明需配置 Embedding、启用向量化并建立向量，且不保证每次命中。
- 画像明确先提议、后确认；生效说明为之后的新会话读取。
- 片尾注明面向 Windows 上的 Pi 用户，引导到项目与安装说明，避免假设 npm 包已经公开发布。

## 文件与复用

- `pi-memory-system-promo-zh.mp4`：完整视频，包含旁白、音乐与内嵌字幕。
- `poster.jpg`：视频封面。
- `subtitles.zh.srt`：独立中文字幕。
- `storyboard.json`：时长、旁白和字幕的可编辑源稿。
- `render.py`：完整绘制、音频合成、编码脚本。
- `requirements.txt`：Python 依赖。

Windows 上需要可用的 FFmpeg / FFprobe 与系统中文字体。安装 Python 依赖后运行：

```powershell
python -m pip install -r requirements.txt
python render.py --prepare-audio --preview --render
```

`--prepare-audio` 使用 edge-tts 联网生成中文合成语音；音乐由脚本用正弦波与包络合成。中间音频、预览图和无声视频写入系统临时目录 `pi-memory-promo-20261011`。成片、封面和字幕写入当前脚本所在目录；不生成逐帧图片目录。

视频图标统一读取 `../icons/main-icon-d4-layer-bridges.svg`，经 resvg 渲染并做超采样缩小，避免复制几何代码导致主图标与视频不一致。

如已有临时音频，可直接使用 `--preview --render`。修改旁白后，应移走对应的临时 `voice-N.mp3`，再重新生成音频。

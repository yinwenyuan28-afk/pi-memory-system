滚动条定位到一个反直觉的原因：**写 `scrollbar-color` 反而会变宽**。实测侧栏滚动条 —— 不指定 = 11px，指定 = 16px 且带箭头；`color-scheme: dark` 才是原生控件（滚动条 / select 弹层 / 复选框 / search 的清除按钮）变暗的前提。最终 = `color-scheme: dark` + `::-webkit-scrollbar`（10px、圆角、透明轨道、hover 变亮）+ 只在 `@supports not selector(::-webkit-scrollbar)` 里为 Firefox 声明标准属性，实测侧栏 11px、页面 10px。

**追加（同日晚）：用户报「L2 场景页鼠标滚动失效」——这是我上一轮引入的回归。** 我把 `overscroll-behavior: contain` 当作"防止滚动传染"的优化加在了 `aside` 与 `.wrap-scroll` 上，原版 CSS 本来没有这个属性。对照实验定位：同一个坐标、同样的滚轮位移，光标落在 L2 块表格那个 `overflow:auto` 但**内容并不溢出**的包装层上时页面 `scrollTop` 纹丝不动；把 `overscroll-behavior` 强制改回 `auto` 后同一个手势立刻把页面滚了下去（作为对照，中性区域在 `contain` 生效时也能滚，说明手势本身有效）。也就是说**容器一带 `contain`，滚轮就被它吞掉，哪怕它根本没有可滚内容**；而 L2 的块表格占了内容列大半、侧栏在内容不长时也不溢出，两处都成了滚轮死区，于是表现为"有时候"失效。修法：`aside`/`.wrap-scroll` 回到默认滚动链接，`contain` 只保留在弹层（打开弹层时拦住滚轮、别滚动背景，这才是它该在的地方）—— 并用 ⑯ 节新增两条断言钉住（分别注入 `aside` 与 `.wrap-scroll` 验证会变红）。教训：**这轮加的好几个东西都是"顺手加的优化"，其中两个（`scrollbar-color`、`overscroll-behavior`）恰恰是让滚动体验变差的那个**；不请自来的样式比缺样式更难发现。

**追加（同日再晚）：用户问「为什么一定要用桥打开，直接打开就显示无写盘桥」——查出两条会丢 `?port=` 的真实缺陷。** 先做了一次关键区分：**"无写盘桥"这句话只在 http 下出现**，双击 HTML（`file://`）时页面顶上显示的是另一句"当前以 file:// 打开"，所以用户看到的不是 file:// 模式，而是"被桥托管、但地址里没有 `?port=`"。顺着这条线索复现出两条路径，都在我们自己可控的代码里：

1. **顶部导航链接不带 query**（`viewer-core.js` 里 `href="' + p.file + '"`）。实测：从 `index.html?port=5174` 点顶部导航去 L2，地址变成 `l2-viewer.html`（query 没了）→ `bridgePort()` 返回空 → 页面立刻冒出 **3 处"无写盘桥"**，写回按钮也失效。而总览页侧栏的按钮是带 `location.search` 的 —— 同一个页面里两种跳转方式行为不一致，纯属漏改。修：导航链接一律 `p.file + escapeHtml(location.search)`。
2. **桥的根路径 `/` 就地返回 index.html**。那份 HTML 引用的是相对路径 `assets/viewer-core.js`，在 `/` 下解析成 `/assets/…`，而静态托管的根是 memoryDB（资源在 `/viewers/assets/…`）→ **CSS/JS 全部 404，连 `window.V` 都不存在，页面是死的**。而桥启动打印的**第一行**正是这个根路径（`[l1-admin viewer-bridge] http://127.0.0.1:5174  profile=…`，终端里可点），等于亲手把用户引到一个坏页面上。修：根路径改成 **302 到 `/viewers/index.html?port=${PORT}`**，并把启动日志第一行改写成"监听 …"，另加一行提醒别手删 `?port=`。

另外把"丢 query"的兜底做成人话：页面顶部新增一条提示，明确说"这个地址没带 `?port=`，补 `<端口>` 即可恢复"，并与 `file://` 的提示**分开两个分支**（两种降级原因不同，合并成一句会让人误以为桥挂了）。

**为什么不做"同源推断端口"（`location.port` 兜底）**：看着能把整类问题一次消掉，但会毁掉"挂任意静态服务器只读浏览"这条用法 —— `npx serve` 起在 3000 时页面同源端口是 3000，却被当成桥端口去请求 `/api/*`，于是从干净的"无写盘桥"变成一堆"响应不是 JSON（HTTP 404）"。所以解析规则保持仅认 `?port=`，改用"修掉丢 query 的来源 + 缺 query 时明说"。

**定位方法值得记一笔**：这次靠的是"**这句文案只在一种模式下出现**"这条线索做的二分（http 无 port ≠ file://），而不是去猜浏览器行为；随后每条结论都在浏览器里复现（点一下导航看 `bridgePort()` 与"无写盘桥"计数）。门禁 126 → 130 项，新增 ⑰ 节四条断言（导航带 query、根路径 302 且带 port、缺 port 有可操作提示、两种提示分属不同分支），并把"导航丢 query""根路径不再 302"两处违规注入验证过会变红。四页与桥的手工复核：根路径 → 落到带 `?port=5176` 的总览页且 `window.V` 已载入、统计行有真实数据、0 处"无写盘桥"；点导航到 L2 保持 `?port=`、0 处"无写盘桥"；手动去掉 query 则 3 处"无写盘桥"+ 顶部可操作提示（`live 块（磁盘）` 显示 `—`，如实反映只有"列目录"这一项不可用）。**注意：桥的根路径修复要重启桥才生效**（查看器 JS 那部分刷新页面即可）。

**本轮验收方式的局限（要记着）**：当前会话模型不支持图像输入，派出去的子代理同样看不到图，所以四页的原始截图我无法判读。替代证据是可量化的：滚动容器与滚动条宽度、字号集合、每对文字的对比度（像素回读）、元素几何与网格列数、温度工具类的实际计算色，以及四页的渲染文本内容（确认无"加载中/尚未加载"残留、无 JS 异常导致的空段）。**而这次的 `overscroll-behavior` 回归恰好说明这些量化项还不够**：它不改变滚动条宽度、不改变字号与对比度，"滚轮能不能滚"这条只有真的滚一下才知道 —— 后续做滚动相关改动时，除了量几何，还要用真实滚轮手势做一次 A/B。总之：**"好不好看"仍需人看一眼**，上面的数字只保证契约与可读性下限。

## 2026-10-09 信息过载治理 ②：L1 卡片信息分层

一张卡原本塞 15 个胶囊（勾选 + 7 个 chip + 8 个 metric），567 张卡合起来 **7,232 个胶囊**，其中 metric 那 8 个数字（eff / hits / 注入 / decay / 活跃天 / 日期 / 相对时间 / id）是**诊断值** —— 要排查衰减或命中时才用得上，扫读列表时是纯噪声。更糟的是首屏 4 张卡里有 2 张的 8 个指标**逐字完全相同**，同一排数字在 200px 内原样出现两次。

改法是**分层而不是删除**：卡片只留一个「多久没动」（相对时间适合扫读），其余整体搬进详情弹层。搬之前先核对了弹层已有哪些 —— eff / hits / decay / days / 日期 / id **本来就在里面，而且 id 出现了两处**，所以这是净去重；唯一真正只存在于卡片的是「注入 / 工具」，搬走等于丢，因此同步补进弹层首屏的第二行 chips，同时把 dl 里重复的那行 id 删掉、把相对时间并进 `createdAt / updatedAt` 一行。

实测：单卡胶囊 **15 → 7~8**（勾选 + 按需出现的状态 chip + 1 个时间），卡片高度明显下降；弹层首屏有 eff / hits / 注入 + id，展开「字段与审计」后 decay / days / createdAt+updatedAt / 最后更新俱在 —— **8 项诊断值一项不少**。门禁：`verify-viewer-deploy` 193/0（⑯⑤ 直接锁 `.card-body .full-content` 的 line-clamp，这批没碰它）、`verify-viewer-quality-parity` 278/0、`check-types` 0 新增。

顺手修了体检脚本一个假阳性：弹层开着时遮罩盖住整页，背景所有元素都会被判成「被遮挡 / 互相重叠」（实测虚报 126 项）。改成弹层打开时只体检弹层内部，关掉后回到真实值 **12 项**（仍是那 12 处刻意的场景名省略号）。

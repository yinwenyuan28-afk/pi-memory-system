**追加（同日晚）：用户报「L2 场景页鼠标滚动失效」——这是我上一轮引入的回归。** 我把 `overscroll-behavior: contain` 当作"防止滚动传染"的优化加在了 `aside` 与 `.wrap-scroll` 上，原版 CSS 本来没有这个属性。对照实验定位：同一个坐标、同样的滚轮位移，光标落在 L2 块表格那个 `overflow:auto` 但**内容并不溢出**的包装层上时页面 `scrollTop` 纹丝不动；把 `overscroll-behavior` 强制改回 `auto` 后同一个手势立刻把页面滚了下去（作为对照，中性区域在 `contain` 生效时也能滚，说明手势本身有效）。也就是说**容器一带 `contain`，滚轮就被它吞掉，哪怕它根本没有可滚内容**；而 L2 的块表格占了内容列大半、侧栏在内容不长时也不溢出，两处都成了滚轮死区，于是表现为"有时候"失效。修法：`aside`/`.wrap-scroll` 回到默认滚动链接，`contain` 只保留在弹层（打开弹层时拦住滚轮、别滚动背景，这才是它该在的地方）—— 并用 ⑯ 节新增两条断言钉住（分别注入 `aside` 与 `.wrap-scroll` 验证会变红）。教训：**这轮加的好几个东西都是"顺手加的优化"，其中两个（`scrollbar-color`、`overscroll-behavior`）恰恰是让滚动体验变差的那个**；不请自来的样式比缺样式更难发现。

**追加（同日再晚）：用户问「为什么一定要用桥打开，直接打开就显示无写盘桥」——查出两条会丢 `?port=` 的真实缺陷。** 先做了一次关键区分：**"无写盘桥"这句话只在 http 下出现**，双击 HTML（`file://`）时页面顶上显示的是另一句"当前以 file:// 打开"，所以用户看到的不是 file:// 模式，而是"被桥托管、但地址里没有 `?port=`"。顺着这条线索复现出两条路径，都在我们自己可控的代码里：

1. **顶部导航链接不带 query**（`viewer-core.js` 里 `href="' + p.file + '"`）。实测：从 `index.html?port=5174` 点顶部导航去 L2，地址变成 `l2-viewer.html`（query 没了）→ `bridgePort()` 返回空 → 页面立刻冒出 **3 处"无写盘桥"**，写回按钮也失效。而总览页侧栏的按钮是带 `location.search` 的 —— 同一个页面里两种跳转方式行为不一致，纯属漏改。修：导航链接一律 `p.file + escapeHtml(location.search)`。
2. **桥的根路径 `/` 就地返回 index.html**。那份 HTML 引用的是相对路径 `assets/viewer-core.js`，在 `/` 下解析成 `/assets/…`，而静态托管的根是 memoryDB（资源在 `/viewers/assets/…`）→ **CSS/JS 全部 404，连 `window.V` 都不存在，页面是死的**。而桥启动打印的**第一行**正是这个根路径（`[l1-admin viewer-bridge] http://127.0.0.1:5174  profile=…`，终端里可点），等于亲手把用户引到一个坏页面上。修：根路径改成 **302 到 `/viewers/index.html?port=${PORT}`**，并把启动日志第一行改写成"监听 …"，另加一行提醒别手删 `?port=`。

另外把"丢 query"的兜底做成人话：页面顶部新增一条提示，明确说"这个地址没带 `?port=`，补 `<端口>` 即可恢复"，并与 `file://` 的提示**分开两个分支**（两种降级原因不同，合并成一句会让人误以为桥挂了）。

**为什么不做"同源推断端口"（`location.port` 兜底）**：看着能把整类问题一次消掉，但会毁掉"挂任意静态服务器只读浏览"这条用法 —— `npx serve` 起在 3000 时页面同源端口是 3000，却被当成桥端口去请求 `/api/*`，于是从干净的"无写盘桥"变成一堆"响应不是 JSON（HTTP 404）"。所以解析规则保持仅认 `?port=`，改用"修掉丢 query 的来源 + 缺 query 时明说"。

**定位方法值得记一笔**：这次靠的是"**这句文案只在一种模式下出现**"这条线索做的二分（http 无 port ≠ file://），而不是去猜浏览器行为；随后每条结论都在浏览器里复现（点一下导航看 `bridgePort()` 与"无写盘桥"计数）。门禁 126 → 130 项，新增 ⑰ 节四条断言（导航带 query、根路径 302 且带 port、缺 port 有可操作提示、两种提示分属不同分支），并把"导航丢 query""根路径不再 302"两处违规注入验证过会变红。四页与桥的手工复核：根路径 → 落到带 `?port=5176` 的总览页且 `window.V` 已载入、统计行有真实数据、0 处"无写盘桥"；点导航到 L2 保持 `?port=`、0 处"无写盘桥"；手动去掉 query 则 3 处"无写盘桥"+ 顶部可操作提示（`live 块（磁盘）` 显示 `—`，如实反映只有"列目录"这一项不可用）。**注意：桥的根路径修复要重启桥才生效**（查看器 JS 那部分刷新页面即可）。

**本轮验收方式的局限（要记着）**：当前会话模型不支持图像输入，派出去的子代理同样看不到图，所以四页的原始截图我无法判读。替代证据是可量化的：滚动容器与滚动条宽度、字号集合、每对文字的对比度（像素回读）、元素几何与网格列数、温度工具类的实际计算色，以及四页的渲染文本内容（确认无"加载中/尚未加载"残留、无 JS 异常导致的空段）。**而这次的 `overscroll-behavior` 回归恰好说明这些量化项还不够**：它不改变滚动条宽度、不改变字号与对比度，"滚轮能不能滚"这条只有真的滚一下才知道 —— 后续做滚动相关改动时，除了量几何，还要用真实滚轮手势做一次 A/B。总之：**"好不好看"仍需人看一眼**，上面的数字只保证契约与可读性下限。

## 2026-10-09 信息过载治理 ②：L1 卡片信息分层

一张卡原本塞 15 个胶囊（勾选 + 7 个 chip + 8 个 metric），567 张卡合起来 **7,232 个胶囊**，其中 metric 那 8 个数字（eff / hits / 注入 / decay / 活跃天 / 日期 / 相对时间 / id）是**诊断值** —— 要排查衰减或命中时才用得上，扫读列表时是纯噪声。更糟的是首屏 4 张卡里有 2 张的 8 个指标**逐字完全相同**，同一排数字在 200px 内原样出现两次。

改法是**分层而不是删除**：卡片只留一个「多久没动」（相对时间适合扫读），其余整体搬进详情弹层。搬之前先核对了弹层已有哪些 —— eff / hits / decay / days / 日期 / id **本来就在里面，而且 id 出现了两处**，所以这是净去重；唯一真正只存在于卡片的是「注入 / 工具」，搬走等于丢，因此同步补进弹层首屏的第二行 chips，同时把 dl 里重复的那行 id 删掉、把相对时间并进 `createdAt / updatedAt` 一行。

实测：单卡胶囊 **15 → 7~8**（勾选 + 按需出现的状态 chip + 1 个时间），卡片高度明显下降；弹层首屏有 eff / hits / 注入 + id，展开「字段与审计」后 decay / days / createdAt+updatedAt / 最后更新俱在 —— **8 项诊断值一项不少**。门禁：`verify-viewer-deploy` 193/0（⑯⑤ 直接锁 `.card-body .full-content` 的 line-clamp，这批没碰它）、`verify-viewer-quality-parity` 278/0、`check-types` 0 新增。

顺手修了体检脚本一个假阳性：弹层开着时遮罩盖住整页，背景所有元素都会被判成「被遮挡 / 互相重叠」（实测虚报 126 项）。改成弹层打开时只体检弹层内部，关掉后回到真实值 **12 项**（仍是那 12 处刻意的场景名省略号）。

## 2026-10-09 局域网调试：桥支持 `--lan` / `--host`

用户要在**别的设备**上调试查看器，要求桥除了 `localhost` 也监听 `172.16.10.x`。

改了两处，缺一处都不成立：

1. **桥的监听面**：从写死 `server.listen(PORT, "127.0.0.1")` 改成按开关组装的监听列表 —— 默认行为**一字不改**（只有环回）；`--lan` 才额外听本机那张局域网网卡（环回保留，"也监听"的字面语义），`--host <addr>` 指定确切地址（`0.0.0.0` 这类通配地址本就覆盖环回，不重复听）。同一份请求处理函数被两个 `createServer` 共用 —— 提出来当变量，否则两份拷贝迟早分叉，而分叉的表现是"从局域网访问少了一半能力"。选网卡的规则（优先 `172.16.10.0/24`，其次其它私有段）单独放进 `lan-addresses.mjs`，**启动器与桥共用**：各写一份就会出"启动器打印 A 地址、桥实际听 B 地址"这种最难查的错配。本机实测有 3 个非环回 IPv4（`172.16.10.4` 有线 / `10.21.202.106` 无线 / `172.30.208.95` VPN），所以候选会全部打印出来，让人能 `--host` 钉死。
2. **页面侧有个必须先修的硬伤**：`viewer-core.js` 的 `bridge()` 把地址写死成 `http://127.0.0.1:<port>`。从别的设备打开页面时，那指的是**那台设备自己的回环** → 所有 `/api/*` 都拿不到数据，页面只剩"桥连接失败"。改成按 `location.hostname` 拼（`file://` 下 hostname 是空串，退回 `127.0.0.1`），于是本机与远端走同一条代码路径。

**这个 bug 最阴的地方在于本机测不出来**：我用 `http://172.16.10.4:5188` 打开页面测第一遍时，数据全在、体检全绿 —— 看 `performance` 记录才发现四条请求全打在 `127.0.0.1:5188` 上，因为桥两个地址都在听、而回环恰好也是这台机器。第二次才发现还有一层：改完 `viewer-core.js` 必须**重新部署**才生效（部署发生在会话激活 / 启动器启动时），我第一遍拿的是旧 JS。重部署后四条请求才变成 `http://172.16.10.4:5188/api/*`。**"本机换地址测不出远端问题"** 这条已写进 `l1-admin/README.md`。

安全上做了三件克制的处理，都没扩大请求范围：**默认不开**（不改默认行为）、**启动就把代价打印出来**（那个地址上没有鉴权、CORS 全开，写端点同网段任何设备可调；`config/` 仍在静态托管之外，局域网也取不到 API key）、**门禁钉住默认值**（⑰ 新增三条：页面按自身 hostname 拼地址、桥默认只监听环回、局域网监听时必须打印"无鉴权"警告）。没有做鉴权 —— 用户没要求，且那会连带改所有页内链接与桥的全部路由；作为选项留在汇报里提出来。

实测：`--lan` 起桥后 `127.0.0.1:5188` 与 `172.16.10.4:5188` 都回 `{"ok":true}`，页面从局域网地址打开取数正常、导航链接带得住 `?port=`、POST 通道也通（用闭集外的 `mode` 值测的，桥在转发 CLI 之前就 400，**一个字节都不写盘**）；一键启动器 `--lan` 会打印"别的设备打开这个地址：http://172.16.10.4:5174/…"，Ctrl+C/超时后端口正常释放、不留孤儿。测试用的两个桥（5188 / 5189）已关，用户原有的 5174 未动。门禁：`verify-viewer-deploy` **208/0**（⑰ 三条新增 + 新 .mjs 的语法检查）、`verify-viewer-write-paths` **145/0**、`verify-viewer-quality-parity` **278/0**、`check-types` 0 新增。

**先说清一处与用户说法的出入**：用户说的是"work_fact 下的二级菜单"，但代码里 `isTask = rec.type === "work_task"`、任务状态筛选也只对 work_task 生效（`filtered()` 里 `r.isTask && r.taskState === f.task`）；work_fact 记录在数据模型里压根没有任务状态这根轴。所以二级挂在 **work_task** 下 —— 挂到 work_fact 上会得到一个永远筛出 0 条或筛错东西的菜单。如果用户的本意是别的（比如把 work_fact 也纳入任务状态），那是数据模型层面的改动，得另说。

三处设计取舍，都是"菜单"这个形态逼出来的：

1. **「非任务记录」归位到类型轴**。它原先藏在任务状态的取值里（`task === "none"`），但语义上一直是类型（= work_task 之外的全部）。两级合并后它不能再挂在 work_task 下面（自相矛盾），所以改成类型轴上的一个虚拟值 `NON_TASK = "!non-task"` —— 用带前缀的字面量是为了不可能与真 type 撞车（真 type 只有 work_fact / work_task / work_method / work_artifact 加历史值）。这是**筛选口径的迁移**，不是新增：`filtered()` 里那一行从 `f.task === "none"` 挪到 `f.type === NON_TASK`，行为不变（实测 530 条）。
2. **行序固定为 schema 声明序**（`V.RECORD_TYPES` + 其余类型按字典序），**不再按计数降序**。菜单里同一项每次都该在同一个位置；按计数排会让行随数据增长互相换位（上一版就是按计数排的，所以 work_method 会跳过 work_task 显示在前面）。顺带把数据里那个孤立的 `architecture`（1 条历史值）如实列出来，而不是静默并进"其它"。
3. **计数一律「存活/总数」**，与一级同一套写法 —— 任务状态与 `deleted` 是两根独立的轴，只报存活会让人以为已删除的任务没有状态。原先那行 `#taskCounts` 提示（"work_task 存活 37 条：待办 19，已完成 9，已废弃 9"）因此删掉：它提供的数字现在就在二级每一行上。

交互上三件事分开，各有各的理由：**展开把手**（▸/▾）只切换二级显隐、不动筛选（"只想看一眼有哪些状态"不该换掉当前视图）；**点二级某状态** = 同时选中 work_task 与该状态（两级同属一个维度，不该要求先点一次类型）；**点一级 work_task** = 选中类型并自动摊开二级（让人当场看见下面还有什么）。离开 work_task 时**清掉状态**，否则会出现"行上显示 work_task·待办、列表却按别的类型筛"这种自相矛盾的屏。二级可收起，但父行在有状态筛选时**必须显示那个状态**（药丸）—— 收起后行上什么都不显示的话，就是"列表被筛过、侧栏看不出在筛什么"。

**踩到一个只有量宽度才能发现的 CSS 坑**：`.btn-list` 一直是 flex 列，按钮作为 flex 项被 stretch 撑满；这次给 work_task 行包了一层容器（里面还要放二级列表），父行立刻缩到**内容宽 140px 而容器 293px** —— 右侧空一大截、把手飘在行中间。根因是 Blink 判 `<button>` 的宽度按内容收缩，放进普通块容器不会撑满。修法是外层也 `display: flex; flex-direction: column`。它不溢出、不错位、体检脚本（越界/裁剪/重叠/遮挡/对比度/点击目标）全绿，在 336px 宽的侧栏里肉眼也很容易看成"就这样"——已固化进 `l1-admin/README.md` 踩坑清单（18 → **19** 条）。

### 为什么是"内置 UMD 文件 + classic script"而不是 Vite 工程

这次重构之前必须先回答一个问题：**谁保证构建产物跟版**。同一套页面 2026-08-23 已经 Vue 化过一版
（`vue-viewer/`：Vite + `package.json` + `src/*.vue`），它死在没有 `node_modules`、没有 `dist`，
最后被 `deploy.ts` 的 `RETIRED_PATHS` 移进 `backups/viewers-retired/`。而本仓库的部署链路
（`memory/viewers/deploy.ts`：按内容哈希逐文件同步 + 写 `viewer-manifest.json` + 桥的漂移检测）
只认"仓库里的普通文件"。所以这一版的取舍是：

- Vue 3.5.43（`vue.global.prod.js` 168 KB）、Element Plus 2.14.7（`index.full.min.js` 1.06 MB +
  `index.css` 361 KB + 暗色 css-vars + zh-CN 语言包）**放仓库**（`viewers/assets/vendor/`，共 1.6 MB），
  出处 / sha256 / 升级步骤写在 `viewers/assets/vendor/README.md`；
- 页面仍是 classic script，**源码即产物** —— 于是哈希清单、漂移检测、退役机制自动覆盖这些库文件，
  一行部署代码都不用改，`file://` 下也照样能渲染（取不到数据，但页面不是白屏）。

### 分工：组件库负责一致性，本仓库 CSS 负责"属于数据的形状"

- **交给 EP**：按钮 / 输入框 / 下拉 / 表格 / 弹层 / 分页 / 复选框 / 折叠面板 / 分段切换 / 提示 / 确认框。
  旧版 987 行的 `viewer.css` 里有一大半是在手工做这些事（7 种按钮外观、4 档尺寸就是这么长出来的）。
- **留在本仓库**（`viewer-theme.css`，734 行）：胶囊（形状编码种类）、度量 token、统计行、卡片、
  条形图 / 直方图、时间线、预算条、规则条目。它们承载的是"这一页怎么表达记忆库"的语义：
  EP 的 `el-tag` 只有五种实心同形，表达不了"虚线 = 未落定 / 点线 = 已搁置"；`el-card` 的
  header/body 结构塞不下"3px 质量条 + 6 行截断正文"的卡片。
- **共享 Vue 层**（`viewer-vue.js`，380 行）：装 EP + 中文语言包、注册九个别域组件
  （`<chip>` `<metric>` `<stat-list>` `<notice>` `<json-details>` `<seg>` `<help-note>` `<bar-list>` `<hist>`）、
  统一挂载入口 `V.vue.mount()`，以及渲染期异常兜底（Vue 默认只把错误丢进控制台，页面看着"半截渲染"
  却没有任何提示 —— 现在会把它摆在页面顶部）。
- **`viewer-core.js` 一个字节没改**：导航 / 版本 chip / 只读横幅仍由它的 `mountChrome` 直接写 DOM
  （`#nav` 与 `#modeBanner` 特意留在 Vue 挂载点之外）。理由：⑰ 节钉住的打开方式契约（页内跳转必须带
  `location.search`、缺 `?port=` 要给可操作提示、桥地址按页面自身 hostname 拼）都在它里面，
  搬进 Vue 只会让那条门禁去断言一段死代码 —— 顺手在 ⑯ 里加了一条"`viewer-vue` 仍调用 `mountChrome`"
  来防止这件事发生。

### 换实现不换语义（逐条验收）

- **端点、请求体、判定条件、文案**：五个页面的 `/api/*` 字面量集合与旧版**逐个相同**
  （`grep -o '"/api/[a-z0-9/-]*"' 旧 | sort -u` 与新 `diff` 为空），写动作的请求体逐个比对过。
- **写盘路径逐条用假桥验证**（`window.fetch` 存根只记录请求体并返回构造响应，真实 profile 一个字节不写）：
  · 任务状态：`POST /api/task-state {ids:["l1_…"], state:"open"}` —— 与旧版同形（`reason` 空时随
    `JSON.stringify` 自然丢弃，与旧版一致）；
  · 纠错预演/执行：`POST /api/l1/fix {id, action:"rewrite", content, evidence}` 与加 `apply:true` 的第二次
    请求**其余字段逐字段相同**；「执行（写盘）」只在预演通过后才出现；
  · 批量：`POST /api/task-state {ids:[两条], state:"done"}` / `POST /api/tombstone {ids:[两条]}`（确认块
    逐条列 id 后再发）；单条墓碑走 EP 确认弹层后才发；
  · 两个"打字确认"闸：重建要键入 `REBUILD`、整库还原要**逐字等于所选备份目录名**才解锁（实测填错一个
    字符立刻禁用回去）；
  · 读写分离同样验过：**每次假桥测试后都回磁盘核对**，两条记录仍是原状态、`deleted:false`。
- **只读模式（不带 `?port=`）五页全测**：只读横幅都在，写动作全禁用，页面不编造数据
  （L1 退化为"静态探测（最近 90 天）"、L3 明说"没读到：MEMORY.md/USER.md/USER-temp.md"）。

### 顺带修掉的旧缺陷

- **L3 的同源数据渲染两遍**：旧版 `#entries`（只读清单）与 `#opsEntries`（带按钮）是同一批数据，
  `#backups` 与 `#opsBackups` 也是。新版**每个数据集只渲染一处**，动作并进那唯一一份；
  MEMORY 组的条目照旧**不给按钮**（写下去会落到语义错误的文件）。实测：MEMORY 组 3 条 / 0 按钮。
- **L1 列表分页**（每页 60 / 120 / 240 / 全部，默认 60）。旧版一次渲染 566 张卡片，改一个搜索词就重建
  整张列表。**语义不变**：「全选当前筛选」与「导出当前视图」作用的仍是筛选结果**全集**，分页只影响画面。
- **弹层里的记录不再靠下标定位**：旧版卡片写 `data-idx`、点击时用 `state.lastRows[idx]` 取回记录 ——
  下标只在"当前这一份渲染结果"里有效。新版直接把记录对象交给 `openModal(row)`，这类 bug 从结构上消失。

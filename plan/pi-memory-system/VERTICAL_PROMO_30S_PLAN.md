# Pi Memory：30 秒竖屏宣传视频策划

> 用户已于 2026-10-12 授权按本稿制作动画，并将帧率调整为 **60 fps**。制作规格为 **30 秒、1080 × 1920、1,800 帧**，中文旁白与内嵌字幕。

## 1. 创意主线

**片名：换个会话，经验接着用。**

用一个开发者与 Pi 的小故事讲清楚：上次说好的排查方法，被整理成记忆，在新的相关会话里重新用上。

观众先看到“怎么又要解释一遍”的熟悉困扰，再亲眼看见一张记忆卡穿过会话切换，帮助 Pi 继续排查。情绪从轻微无奈变成“这下接上了”。

核心主张：**为 Pi 提供长期记忆支持。**

观众看完应记住三个信息：

- 对话里有价值的经验可以积累下来。
- 在新的相关工作中，可以按需找回。
- 扩展叫 **Pi Memory**，安装入口在 **pi-memory.com**。

### 为什么采用这个故事

网站已经有“支付回调：订单号 → 签名 → 幂等记录”的对话演示，可以直接复用事实素材。三个步骤足够具体，能让观众看出前后确实用了同一份经验，也容易用三个短标签表现。

旧宣传片偏向完整介绍记忆流程。竖屏短片把注意力集中在一次成功接续上，视觉动作围绕同一张卡片展开。图标、深绿色和柔和薄荷色延续现有品牌，画面重新按手机观看设计。

## 3. 角色与画面语言

### 你：右侧

简洁的开发者头像与右对齐气泡。开场通过光标停顿、半截输入和一个小小的“……”表现无奈；接续成功时变成确认动作。人物表情可以落在单独的线条头像上，品牌图标保持原样。

### Pi agent：左侧

使用带 `π` 的终端小头像，气泡左对齐。通过光标和三点输入提示表现思考。画面角色标为 `Pi agent`，避免把扩展图标误当成 Pi 本体的标志。

### 记忆：贯穿故事的同一张便签

从上一段对话抽出三个关键标签，折叠成一张方法卡。卡片带一个固定的小书签缺口，方便观众在会话切换后认出它。新问题出现时，其他卡片退后，这张相关卡片被取回并展开为 Pi 的回答步骤。

记忆整理与新会话之间明确显示时间推进。观众看见的是跨会话复用，不会把几秒钟的剪辑误解为每句话都会立即提取。

## 5. 镜头内的具体节奏

### 00–03 秒：先让观众认出自己的困扰

- 00.0 秒即有画面和标题，直接进入新会话。
- 00.0–00.8 秒：你发出 `继续排查。`。
- 00.8–01.8 秒：Pi 显示 `之前怎么查的？`。
- 01.8–03.0 秒：光标停顿，头像旁出现小小的 `……`，给观众一秒认出“又要解释”的感觉。
- 角落标明 `未带回上次方法`。这是该示例的初始条件；不表达 Pi 的每个新会话都必然丢失所有背景。

### 06–10 秒：旧方法要读得清

- 先出现 `上一次会话`，再出现用户气泡。
- 三个步骤按“订单号、签名、幂等记录”依次轻亮，完整链路至少保留两秒。
- 气泡按短句分段出现；这条方法不使用漫长的逐字输入。
- Pi 的确认在下方出现，保留短暂阅读时间，然后进入时间推进。

### 10–14 秒：把抽象的“记忆”变成看得见的东西

- 前半秒通过日历翻页和背景里的简化对话变化压缩时间。
- 接着对话内的关键词划线，滑出成为卡片上的三个步骤。
- 方法卡完整露出后轻轻缩小，进入记忆卡片组。
- 画面只出现方法卡正文。后台处理日志、模型推理和层级名称留在制作说明中。

### 14–23 秒：这是全片的核心证明

- 从 14 秒开始清楚显示 `新的会话`。
- 用户问题先出现，随后方法卡被取回，最后 Pi 显示回答。三个动作有清楚因果关系。
- 18–21 秒：回答按三行出现，每行间隔约 0.7–0.9 秒。
- 21–23 秒：完整答案保持可见。确认动作可以是鼠标点击或头像旁的小勾。
- 14–23 秒持续保留可读说明：`示例：已配置 Embedding，记忆已建立向量`。这条说明放在字幕上方的固定位置，避免闪过。

### 26–30 秒：给行动信息留足时间

- 品牌、网站和安装命令在 26 秒进入，最迟 26.5 秒全部到位。
- 最后的 3.5 秒基本静止，网站和命令不逐字输入。
- 命令只展示扩展的安装步骤，旁边标为 `已有 Pi？安装扩展`。
- 可读注记：`当前支持 Windows · 完整安装与向量配置见网站`。

## 6. 连贯旁白稿与字幕切分

整段旁白建议约 23–26 秒读完，其余时间留给停顿、视觉反馈和片尾。实际时长以配音样音为准，不通过硬加速把超时音频塞入分镜。

>
> 说过的方法，还得重讲。
>
> 把对话里的方法，留下来。
>
> 累积的对话，在后台整理成记忆。
>
> 配置语义召回，
>
> 新会话，也能找回相关方法，接着查。
>

表中的 `／` 表示换行，不出现在成片中。字幕最多两行；对白有自己的气泡位置，不再额外加一套角色配音字幕。

前两句带一点“又来一次”的无奈，记忆整理时语气恢复轻松，召回后有推进工作的确定感。保持自然语气。

两位角色分居左右，但气泡沿竖直方向展开。每个镜头只有一个主要阅读目标；开始读下一句话时，上一段可以变淡或移到上方。

### 色彩与品牌

- 背景沿用旧片的深绿，推荐 `#10251C`；保持大面积安静。
- 正文用接近米白的 `#F3F3EA`。
- 主要绿色沿用当前图标的 `#379B70`；需要强调时少量使用柔和薄荷色 `#A9D9BD`。
- 开场无奈状态可以用一小点低饱和暖色，转到记忆整理后恢复绿色。
- 主图标直接复用 [main-icon-d4-layer-bridges.svg](../../assets/icons/main-icon-d4-layer-bridges.svg)，保持当前顶层和连接线颜色。
- 图标在产品出现和片尾使用，其余镜头由人物与记忆卡承担叙事。

### 动效

- **开场重复：**打字声重复一次，便签轻微挤压，制造“熟悉又烦”的感觉。
- **后台整理：**关键词抽出、卡片折叠、小勾落下，让“提炼”具体可见。
- **时间变化：**日历或会话编号翻页；转场持续约 0.3–0.5 秒。
- **按问题找回：**无关卡片退到背景，相关卡片前移。靠选择表现关联性。
- **接续工作：**卡片内容逐步成为 Pi 回复，最后恢复当前任务的推进动作。

动效主要服务于“问题 → 找回方法 → 继续任务”这条因果链。镜头进入快，正文阅读有停顿；后半段比开场稳定，给观众一种工作已经接上的感觉。

## 8. 配乐与音效安排

建议使用有轻微律动的电子节拍，约 100–115 BPM；音乐可来自有明确使用许可的素材或原创合成。配音出现时压低音乐，优先保证手机外放能听清。

| 段落 | 声音作用 |
| --- | --- |
| 00–06 秒 | 消息音、短打字声；Pi 追问后留下小停顿，帮助笑点成立 |
| 06–14 秒 | 音乐渐入；方法标签和记忆卡的落位音让信息被“收好” |
| 14–23 秒 | 召回用单次清楚的提示音；回复步骤的声音轻且短 |
| 23–30 秒 | 节奏稳定，品牌提示音后自然收尾 |

角色对白不再配声。一位旁白足以讲清逻辑，也能为气泡阅读留空间。

画面作为产品流程动画，用虚构的支付问题和示例数据。说明 `流程示意` 从产品出现时持续显示，字号可读。视频配文进一步说明：语义召回需要配置服务、建立向量，结果受相关性与就绪时间影响。

制作阶段需要核对的边界：

- 前两个镜头展示未带入旧方法的情境，不概括 Pi 的全部记忆能力。
- 不把时间压缩表现为每句话立即完成后台提取。
- 不使用“永不遗忘”“每次必定命中”“完全不占上下文”“零成本”等绝对承诺。
- “按需带回”说明的是相关记录的选择和预算控制；正式背景、工具说明与主动工具结果仍有上下文成本。
- 自动插入的记忆块不写入主会话 JSONL，是可以在后续技术介绍里展开的亮点；本片将它转化成“相关卡进入当前任务”的视觉表达。
- 本片集中展示方法记忆。画像确认、场景整理、记忆管理和技能提炼可作为后续各自独立的短片主题。

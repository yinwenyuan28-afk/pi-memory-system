# 记忆模型与向量化交互式配置

为扩展增加类似 Pi `/model` 的交互式配置入口，让用户在 pi 终端中选择后台 LLM、填写/确认 Embedding 服务，并清楚控制向量化是否开启；另提供只读 `/my-memory:model:peek` 查看当前实际配置与生效状态。

## 目标

- 不再要求用户手工编辑 `application-propertis.json` 才能配置模型。
- 后台 LLM 从当前 Pi `modelRegistry` 的可用模型中选择，并按当前 profile 保存。
- Embedding 配置使用独立步骤输入 OpenAI-compatible endpoint 等信息；不把普通对话模型误认为可用的 embedding 模型。
- 清楚展示向量化开关、500 条默认启用阈值及其对 L1 语义召回/去重的影响。
- `/my-memory:model:peek` 只读展示当前模型配置和向量化状态，不写文件、不发网络请求、不显示密钥值。
- 取消或任一步失败时不写入半成品配置；保留现有配置与旧格式读取兼容。

## 已确认决策

| 决策 | 理由 | 被否选项 |
|---|---|---|
| 向量化首次保持关闭；在向导里明确询问是否更改；不自动回填 | 避免用户不知情地产生远程调用和费用 | 配好 Embedding 后自动启用并回填 |
| 增加 `/my-memory:model:peek`，严格只读且不联网 | 用户要求只看不写；peek 应反映配置与本地向量状态 | 使用会初始化数据库的通用向量库单例 |
| 向量化触发阈值按最近 365 天有效 L1 记录数执行 | 修复现有调用未传 recordCount、阈值配置实际未生效的问题 | UI 显示阈值但运行时忽略 |

## 现状勘察

- `application-propertis.json` 是统一配置中心，`model.llm` 缺省时回退当前 Pi 模型；`model.embedding` 要求 `apiKey` 和 `url`。
- `vectorization.enabled` 默认 `false`，`triggerThreshold` 默认 `500`。代码审查发现 L1 提交之前没有传记录数，阈值实际未生效；本计划会接上门控，按最近 365 天有效记录数判断。
- L1 自动注入和 `recall_l1_records` 都依赖向量召回。不开启/未达到阈值时，新增 L1 记忆仍会落盘，但不会进入向量召回；因此 L1 语义召回和自动注入明显减弱。`embed_and_search` 不可用时会走降级路径，L1 去重效果和效率也可能下降。
- Pi 官方 `/model` 提供交互式模型选择；扩展 API 提供注册 slash command、`ctx.ui.select`/`input` 和 model registry 能力，可以实现类似交互。
- Pi 的常规模型目录面向对话模型；扩展当前 Embedding 客户端要求 endpoint URL/API key，因此 Embedding 需要单独收集和校验服务设置。

## 流程

### 主路径

1. 用户执行扩展提供的 `/my-memory:model` 命令。
2. 菜单显示当前后台 LLM、Embedding 设置状态、向量化状态，并允许进入对应配置步骤。
3. 后台 LLM 步骤从 Pi 可用模型列表选取，确认后只更新当前 profile 的 `model.llm`。
4. Embedding 步骤读取已有配置作为默认值，逐项收集 endpoint、API key、模型名和维度；保存前校验必填字段，成功后更新当前 profile 的 `model.embedding`。如果已有向量库，所选维度必须与其表结构一致；改变维度暂不由向导自动迁移。
5. 向量化步骤说明“达到阈值后会为 L1 记忆生成向量，支持语义召回和去重”，让用户明确选择开启/关闭，并可调整阈值；不得在仅配置 Embedding 后静默开启。
6. 开启后若已有未向量化记录，提示用户运行现有回填命令；回填行为仍由现有命令负责。L1 提交在最近 365 天有效记录数达到阈值后才开始新向量写入。
7. Embedding 配置和服务在进程级缓存；保存后提示重启 Pi，确保主进程和后台子代理使用新配置。

用户执行 `/my-memory:model:peek` 时，命令只读取当前 profile 的配置和本地向量/记忆统计，报告后台 LLM 是显式配置还是跟随当前模型、Embedding 是否配置（密钥只显示已配置/未配置）、向量化开关与阈值、当前 L1 记录数及已向量化数；该命令不修改任何文件或数据库、不调用远端服务。

### 意外与边界

| 场景 | 处理 |
|---|---|
| 用户在任一步取消 | 退出当前步骤，不写入该步骤未确认的变更。 |
| 当前 Pi 没有可选模型 | 提示先通过 Pi `/login` 或 Pi 自身配置添加可用模型，不写入空配置。 |
| Embedding URL/API key 缺失或校验失败 | 保留之前配置并显示可操作错误，不开启向量化。 |
| 磁盘写入失败 | 保留已有文件；向用户报告失败，不显示成功状态。 |
| 只选模型而未配置 Embedding | 后台 LLM 配置生效；向量化保持当前状态，依赖 Embedding 的操作按现有降级/报错行为处理。 |
| 开启向量化但当前记录数低于阈值 | 配置保持开启；现有 readiness gate 在达到阈值前不写入向量，状态说明需要保留这个事实。 |
| 用户试图改变既有向量库维度 | 向导拒绝保存并告知当前表维度，避免后续插入/召回报错；表结构迁移不在本计划内。 |
| 已有旧版 `memory-system-model.json` | 继续由现有兼容读取逻辑兜底；交互保存写入统一配置中心，不删除旧文件。 |

## 实施记录

- 新增 `/my-memory:model` 交互菜单：Pi 模型选择、Embedding 配置、向量化开关和阈值设置。
- 新增 `/my-memory:model:peek`：展示配置状态、最近 365 天 L1 记录数、向量库记录数和语义召回可用情况。
- 修复 `triggerThreshold` 实际未生效的问题：L1 commit 现在把最近 365 天有效记录数传给向量化闸门。
- 修改 Embedding 设置后提示重启 Pi；已有向量库维度不匹配时拒绝保存。
- 文档已更新；类型检查通过。未在真实 Pi TUI 内手动走完整交互，API Key 输入框没有密码掩码，向导会明确提醒。

## 不做的事

- 不替用户调用 Pi `/login` 或修改 Pi 的 `auth.json` / `models.json`。
- 不把普通 LLM 模型自动当作 Embedding 模型。
- 不删除旧模型配置文件，不改变现有旧配置回退行为。
- 不自动开启向量化或自动运行历史回填。
- `/my-memory:model:peek` 不做配置验证请求、回填或任何隐式修复。
- 现有向量表的维度迁移不属于本计划；已有向量库时配置器拒绝修改维度。
- 不更换 Embedding HTTP 客户端、不扩展到非 OpenAI-compatible API。

## 风险/待确认

- `/my-memory:model:peek` 的只读范围已确认：本地配置与本地统计；不发测试请求、不展示 API key 明文。
- Pi 当前安装版本的 `modelRegistry` 可用模型列表、交互 UI 需以本项目锁定的 Pi API 为准；交互入口不可依赖 Pi 私有菜单实现。
- Embedding 配置和服务存在进程级缓存；设置命令提示重启 Pi 后生效。
- 最近 365 天记录数需要在每次开启向量化的 L1 提交中读取，以执行触发阈值；若以后数据量明显增长，需评估更低成本的计数方式。
- 真实 Pi TUI 手动 smoke check 尚未完成；首次在 TUI 使用时重点确认选择器的长标题显示、输入取消行为和 `peek` 只读输出。
- Embedding API key 继续保存在 profile 配置文件，和当前行为一致；需要在命令交互中避免把密钥回显到通知/状态栏。

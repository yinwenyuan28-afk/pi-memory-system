# 收敛 L1 提取提示词契约

修正 L1 编排提示词、code/chat 提取规则、去重规则与工具实际行为之间仍未对齐的约定，降低错误归场景、错误去重和批次失败的概率。

## 目标

- 每项 L1 行为只有一个明确的契约所有者，编排规则与模式规则不互相冲突。
- 提示词中的场景回退、无记忆批次、去重状态和召回批量大小都符合当前实现。
- 时间戳及出处 ID 的格式明确，模型不把归档时间当作事件时间，也不产生无效出处。
- 变更有对应的现有验证脚本或提示词契约检查覆盖。

## 已确认决策

| 决策 | 理由 | 被否选项 |
|------|------|---------|
| L1 进度使用每个 L0 分片的字节偏移；Pi 消息 ID 取外层 entry ID，另存 sourceLine 作为缺失 ID 时的稳定回退 | 时间戳可能重复，不能安全充当行游标；Pi 消息正文通常没有 id | 用 recordedAt 继续做游标；把时间戳当作消息 ID |
| 当前计划仅处理剩余的提示词与契约问题，不重新设计已修复的游标和项目归属实现 | 避免重复改动已确认的实现 | 将游标/项目归属重开为待讨论事项 |
| `agents/l1-extractor.md` 负责流程、工具调用和提交；模式提取文件负责类型与提取规则；`dedup.md` 负责去重裁决；工具实现定义运行时边界 | 让重复内容有可追溯的权威来源 | 再新增一份完整重复所有规则的总提示词 |

## 剩余问题与修复方向

| # | 问题 | 现状依据 | 修复方向 |
|---|------|----------|----------|
| 1 | 场景规则互相矛盾，且失败回退描述过时 | 编排提示词先要求只能复用池内 ID 或新建，后又说场景判定失败时不填字段并由服务端按同 cwd 最近场景回退；实际 `scene-pool.ts` 对缺少归属的记录写入未归类占位，不会按 cwd 猜场景。code/chat 文件还要求即使没有可提取记忆也输出场景切分，但场景只随记忆记录提交，空 `memories` 不会创建场景 | 统一为“有记忆才为记录选择现有场景或新建场景；不能判断时明确未归类”。无记忆批次不创建场景，但仍提交空 records 与 nextCursor，完成游标推进。删掉按 cwd 猜场景的说法和空场景输出要求 |
| 2 | 去重回退路径对删除标记的处理与 LWW 数据语义冲突 | 编排提示词写着从最近 30 天记录中“忽略 `deleted:true`”，但同文件后文又说明必须按同 ID 最后一次写入判断存活；核实当前提交实现就地将历史行标为 deleted，并非追加墓碑；历史文件仍可能存在同 ID 多行，不能先丢弃 deleted 再折叠 | 明确按分片顺序对同 ID 折叠为最后一行，只把最后状态为 active 的记录放入候选池；删除标记不能被简单忽略，否则旧记忆会重新进入候选并被重复更新 |
| 3 | 向量召回的一次批量条数没有上限处理 | L1 提示要求对本批全部新记忆一次调用；`embed_and_search` 的批量查询硬上限为 50，而 25 条消息可能提取出超过 50 条记忆，超限时工具返回错误 | 按最多 50 条 query 分块调用，按 query 索引合并结果并保留各自 queryVector；部分块失败时只对失败项走已有的文本回退路径，避免整批失去召回 |
| 4 | 事件时间输入格式写成 ISO，但 L0 实际 `timestamp` 是 epoch 毫秒 | `extract-code-personal.md` / `extract-chat.md` 的模板称消息时间为 ISO；`session-parser.ts` 保存 Pi 的 timestamp 数值，`recordedAt` 才是 L0 归档时间。两种时间含义不同 | 明确区分事件 `timestamp` 与归档 `recordedAt`；在提示词中规定从 epoch 毫秒换算 ISO 8601 后再推断事件时间，缺失或无效时不猜；归档时间不得代替事件时间 |
| 5 | 记忆出处与情境消息范围的字段关系没有形成一致的输出校验契约 | 提取规则同时输出外层 `message_ids` 和每条记忆的 `source_message_ids`；项目证据又要求 message_id 属于该记忆自己的 source 列表。编排提示词、code/chat 两套示例重复定义这些字段，容易只填外层列表或引用批次外消息 | 明确外层列表只描述情境覆盖范围；每条记忆必须独立列出实际支持该记忆的本批 source IDs，且项目证据只能引用该记忆的 source IDs。统一 code/chat/schema 示例，并用提示词契约检查防止再次漂移 |

## 流程

### 主路径

1. 以当前实现为准核对场景解析、空 records 提交、LWW 读取、向量查询上限、L0 时间字段和项目证据校验入口。
2. 按上表分别修改编排提示词、code/chat 提取提示词与去重提示词；工具说明只保留对调用者有用的接口边界，不复制整套业务规则。
3. 对去重召回步骤补充 ≤50 条分块及按索引回填向量的操作说明；说明查询结果不足、部分失败和全部失败时的处理方式。
4. 同步更新工具 golden 与现有验证脚本，使其检查场景回退、LWW 删除态、分块上限、时间格式和 provenance 约束。
5. 执行提示词契约验证、L1 场景/游标验证及类型检查；根据结果修正文档与断言。

### 意外与边界

| 场景 | 处理 |
|------|------|
| 整批没有值得保留的记忆 | 提交 `records: []` 和读取器给出的完整 nextCursor；不登记空场景，避免重复读取同一批 |
| 场景无法确定或 scene_id 不在场景池 | 落未归类占位并返回警告；不按 cwd 猜测，也不伪造场景 ID |
| 最近 30 天内同一 ID 出现 active 与 deleted 行 | 按最后写入状态折叠，deleted 记录不作为活动候选 |
| 新记忆总数超过向量工具单次上限 | 切成不超过 50 条的批次；每个结果按 query 索引归回原记忆 |
| 一部分向量批次失败 | 保留成功批次结果；仅对失败部分走文本回退。全部失败时才对整批启用既有回退 |
| 消息 timestamp 缺失、非数值或不可解析 | 不推断具体事件时间；不得以 recordedAt 冒充事件时间 |
| 项目证据引用了批次外消息或不属于该记忆的来源 | 提示词要求剔除该证据；写入校验继续作为最终防线 |

## 实现步骤

1. 先核实空 records 是否推进游标、场景 fallback 写入内容、30 天记录扫描排序和向量批量结果结构；把核实结论回填本计划。
2. 完成场景与空批规则收敛，并清理过时同 cwd 回退描述。
3. 明确最近记录的 LWW 折叠与向量召回分块行为。
4. 修正两套提取提示词的时间格式，并统一 source IDs 与 JSON 示例。
5. 更新 golden / 验证断言，运行相关验证和类型检查。

## 不做的事

- 不重开已经完成的 L1 per-shard cursor 或 Pi 外层消息 ID 改造。
- 不重开已经完成的 L1 `metadata.scope` / 项目证据归属实现。
- 不改变 L1 四种 code 记忆类型、三种 chat 记忆类型或价值校验判据。
- 不重构 L2/L3 提取提示词、向量数据库或整个提示词注册机制。
- 不以提示词文字替代 `l1_commit`、项目证据或向量工具的服务端校验。

## 风险/待确认

- 当前“项目归属”和“游标安全”已在此前修复；本计划只触及提示词契约及其必要验证，不改变其方案。
- 向量查询分块后，候选池会比单次批量更大；实施时需确认候选去重、queryVector 对应关系和每条记录裁决边界。
- 最近 30 天文本回退必须按 LWW 归并；若现有读取代码已提供正确折叠，应只修提示词和验证，不重复实现读取逻辑。
- 是否需要调整 `memory/search/embedding/tool.ts`，由第一步对现有结果结构的只读核实决定。

## 核实与实施记录

用户于 2026-10-04 明确要求核实问题并动手修复，批准执行本计划。五项问题均已核实并完成修复。

- 场景实现确实只回退到未分类占位；空 records 提交能够保存完整游标，且不改变场景池。两套提取规则已删除空场景输出要求。
- 去重提示词确实存在“忽略 deleted”与最后状态折叠冲突。当前提交实际就地标记旧行，原计划中的追加墓碑说法已纠正；现有 record-loader 已正确折叠，不重复修改实现。
- 向量工具确实限制单次最多 50 queries，结果 index 是块内索引。已补充分块映射、仅失败项回退、成功空候选、候选完整正文读取及改写内容不得复用旧 queryVector 的规则，无需修改工具实现。
- L0 timestamp 确实是 epoch 毫秒或 null。已统一事件/归档时间说明；来源证据的旧 ID 回退此前仅接受字符串时间戳，现已同时接受有限数值时间戳，并覆盖 sourceLine 回退。
- 场景覆盖 IDs 与每条记忆出处此前没有统一约束。现要求每条记忆独立列出本批内同会话的实际出处，项目证据只能引用自身出处；公共去重输入契约放在模式章节之前，确保 code/chat 都会读取。
- 小型实现加固：修正 read-tool 中游标联合类型的窄化，并明确 timestamp/sourceLine 返回类型；验证脚本迁移到 v2 游标，临时测试配置关闭远程价值校验，使集成检查可离线重现。
- 已同步工具 golden、架构说明及计划看板。保留此前项目归属与游标修复，不重开其设计。

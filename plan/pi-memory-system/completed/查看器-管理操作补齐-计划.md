## 三条硬约束（决定了实现形状，先写下来免得白干）

1. **L1/L2 的"手动触发"从桥侧够不着。** 桥是独立进程，而 `triggerManual` 依赖主进程的
   `cachedCtx` + executors + `kick()`；全仓库只有 L3 有一条**跨进程**通道：
   `{memoryDB}/l3/pending-trigger.json`（`memory/l3/signal.ts`，写一次 = 请求一次，主进程
   `agent_settled` 时读后即删）。
   ⇒ 本轮把这条通道**泛化**给 L1/L2（`memory/pipeline/pending-trigger.ts`），三个层一套机制。
   **触发语义必须如实写在界面上**：它只是"请求入队"，真正执行要等 pi 会话跑完一轮
   （`agent_settled`）；pi 没开就不会动。
2. **桥会剥掉查询串。** `viewer-bridge.mjs:149` 是 `req.url.split("?")[0]`，所以
   **GET 端点不能带参数**；需要参数的读操作一律走**路径段**（`/api/l2/scene-pool/report`），
   写操作一律 POST + JSON body。
3. **桥是单线程、`execFileSync` 同步。** 长任务（向量回填/重建、场景池 cluster）会把整座桥
   卡住。⇒ 回填/重建用**长超时 + 页面阻塞式"运行中"**，并且重建要求用户打字确认；
   场景池 `cluster` 本轮不上界面（见"不做的事"）。

## 端点契约（冻结）

新增写入一律：**默认 dry-run，必须显式 `apply:true` 才落盘**；破坏性操作额外要求
**打字确认**（`confirm` 字段必须等于约定的字面量，副验在桥里做，UI 只是提示）。

## 各操作语义（与既有实现对齐，不新造口径）

- **L1 纠错**：`runFix` 的三道闸（证据 ≥ 阈值、24h 防抖、高价值保护）原样保留；`force` 只解
  高价值闸。审计是**写进 content 的文本标注**（`【YYYY-MM-DD L1 修正：…】`），外加
  `rewrite.mjs` 的 `metadata.l1Cleanup` —— 界面要把"审计在正文里"讲清楚，别让人以为有独立审计键。
- **L1 还原**：`rollback.mjs` 是**整库替换**（删掉当前所有 `.jsonl` 再复制备份），不是单条撤销。
  界面必须写"这是整库还原"，并要求输入备份目录名确认。
- **L2 归档/恢复**：`archiveSceneBlock`/`restoreSceneBlock` + `reconcileArchive` + `syncSceneIndex`，
  与原命令同序（index.ts:1413 / :1454）；**锁用 L2 run-lock**（不是 L1 的 write-lock）。
- **L2 播种**：`scene-pool.mjs seed` 的提案格式是 `{scenes:[{name,aliases,note?}]}`；页面提供
  一张可增删的表；`cluster` 的输出格式与之不同且需调 embedding，**不做自动转换**。
- **L3 条目编辑**：`l3_edit` 的编排（add/update/delete + 预算闸）目前内联在工具的 `execute()` 里，
  抽成 `memory/l3/edit-core.ts` 的 `applyL3Edit(...)`，工具与 CLI 共用（避免第三份口径）。
- **L3 并入**：用户 2026-09-28 裁定 live `USER.md` 不被自动改写、并入由用户手工完成。界面按钮
  仍是"用户手工"，只是给了工具：写前备份 live → 写入合并结果 → 记审计；并提示**运行中的会话
  需 `/reload` 才会读到新画像**（注入快照是进程内的）。
- **L3 还原**：备份文件名不含"捕获自 temp 还是 live"的信息，因此**统一还原到 `USER-temp.md`**
  （L3 唯一的写目标），要上 live 再走"并入"。这条语义写在界面与 README 上。

## 不做的事（明确记录）

- **场景池 `cluster`**：结果格式与 `seed` 提案不同，需要人给场景命名，且要调 embedding（慢）；
  本轮只把只读的 `report` / `merge-report` 上界面，`cluster` 仍走 CLI。
- **把 L1/L2 触发做成"立即执行"**：架构上做不到（见硬约束 1）。界面如实写"等待 pi 会话消费"。
- **恢复墓碑写回**、**L2 成员改派直写 `scenes.json`**：前者不在清单内，后者已有 `seed` 通道。

## 风险

1. **L3 并入是本轮唯一写 live 画像的路径**，写错会影响注入内容 ⇒ 强制备份 + 确认串 + 逐字校验。
2. 长任务（回填/重建）期间桥不可用 ⇒ 页面明确"运行中，勿重复点击"，并显示耗时。
3. `rollback` 整库替换不可逆（除备份）⇒ 双确认（`apply` + 备份名）。
4. 新增 13 个写端点把桥的攻击面放大（CORS 全开）⇒ 保持仅 127.0.0.1，README 里把这条列入
   已知观察项（既有条目已记此事）。
